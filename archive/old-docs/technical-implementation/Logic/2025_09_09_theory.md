### **🎯 Ключевая идея: Salary Ceiling Effect**

```yaml
Эмпирическое наблюдение:
  Developer с 10 навыками ≈ Developer с 20 навыками (same salary)
  IF: одинаковая роль + одинаковый уровень компании
  
Научное объяснение:
  - Работодатель использует ~25% от всех твоих навыков
  - 75-80% роста зарплаты зависит от софт скиллов (Stanford Research)
  - "Skill saturation" блокирует горизонтальный рост зарплаты
```

### **📊 Научное подтверждение теории:**

#### **1. Исследования о софт скиллах vs зарплата:**
- **Stanford + Carnegie Foundation**: 75-80% успеха топ-менеджеров = софт скиллы
- **HeadHunter 2024**: 78% IT-компаний требуют софт скиллы как **обязательные**  
- **GeekBrains 2025**: 56% разработчиков подтверждают блокировку роста из-за софт скиллов

#### **2. T-Shaped Professional Theory (IDEO + McKinsey):**
```yaml
Horizontal Skills (ширина): 20 языков программирования
  ↳ Impact на salary: Минимальный после достижения базового уровня
  ↳ Impact на employability: Высокий (легче найти работу)

Vertical Skills (глубина): Leadership + Responsibility + Expertise  
  ↳ Impact на salary: Максимальный (exponential growth)
  ↳ Impact на career progression: Критический для вертикального роста
```

```yaml
2. Proven Responsibility:

   - Measurable impact на business outcomes

3. Leadership Motivation:
   - ЖЕЛАНИЕ нести ответственность за других

   - Индикатор: Добровольная помощь коллегам, менторство

4. Growth Opportunity Availability:
   - Компания имеет growth headroom для вертикального роста  
   - Timing: подходящий момент для продвижения
   - Индикатор: Expanding teams, new projects, leadership changes
```

### **🏢 Закон внутрикорпоративного вертикального роста:**

#### **Эмпирическое правило:**
```diff
❌ Неэффективный путь:
- Programmer CompanyA → Team Lead CompanyB  
- Риск: воспринимают как недостаток experience
- Success rate: ~15-25% (низкий)

✅ Эффективный путь: 
- Programmer → Team Lead (внутри CompanyA) → Team Lead CompanyB
- Преимущество: proven track record + внутренние рекомендации  
- Success rate: ~65-75% (высокий)
```

**Причины эффективности внутреннего роста:**
- **Trust Factor**: Коллеги знают твои soft skills на practice
- **Context Knowledge**: Понимание бизнес-процессов компании  
- **Risk Mitigation**: Меньше риска для HR при продвижении знакомого человека


Есть доказанный объем необходимых скиллов
1) Вариант - горизонтальный рост без роста ответственности: Ты можешь расти горизонтально (грейд), изучая всё больше доменную зону, изучая весь проект, становишься готовым брать задачу одной и той же сложности но уже в любой части проекта. Базовый минимум, который от тебя требует руководитель. При таком подходе, ты будешь normal performer - не будет повышения грейда и ЗП, но и не выгонят.
2) Вариант - горизонтальный рост с ростом ответственности. Изучаешь и доменную зону и берешь более сложные задачи. Так ты растешь 


Есть желание у пользователя иметь больше ответственности
Есть возможность у работодателя дать пользователю больше ответственности

Испытательный срок на вертикальное повышение, если не устраивает или не проходит, то возврат к предыдущей роли. Если задержался в роли более чем на полгода, то значит справился со своей ролью: и тебе она понравилась, и руководство довольно твоими результатами. Скорее так, неподтвержденные софт скиллы не ценятся (твоя потенциальная готовность что-то делать != твоя фактическая способность). По моей теории, в хардскилы верят, и проверяют на техсобесах именно их. То есть могут дать грейт поверив тебе

```typescript
async detectSkillSaturation(userProfile: UserProfile): Promise<SkillSaturationAnalysis> {
```

```yaml
Critical Questions для WayMates:

1. Результативность:
   - Какие конкретные результаты показала команда под твоим руководством?
   - Выполнены ли проекты в срок, в бюджете, с качеством?

2. Продолжительность и причины:

3. Признание успеха:
   - Были ли награды, поощрения, благодарности от руководства?
   - Рекомендовали ли тебя для следующих management ролей?  
   - Просили ли коллеги/джуниоры твоего менторства?

4. Личная мотивация:
   - Понравилось ли тебе управлять людьми vs техническими задачами?
   - Чего было больше: satisfaction от team success или frustration?
   - Готов ли повторить этот опыт в больших масштабах?

5. Конкретные обязанности:
   - 1-on-1 meetings, performance reviews, conflict resolution?
   - Планирование ресурсов, roadmap, stakeholder communication?  
   - Hiring decisions, зарплатные вопросы, firing decisions?
```

#### **🎯 WayMates Proven Responsibility Algorithm:**
```typescript
interface ResponsibilityEvaluation {
  role: string;                    // "Team Lead", "Project Manager" 
  durationMonths: number;          // 8 месяцев
  endReason: 'promoted' | 'lateral_move' | 'demoted' | 'voluntary_return';
  
  results: {
    projectsDelivered: number;
    budgetPerformance: 'under' | 'on_time' | 'over';  
    teamSatisfactionScore: number; // 1-10 from team feedback
    stakeholderFeedback: 'positive' | 'neutral' | 'negative';
  };
  
  recognition: {
    formalAwards: boolean;
    mentorshipRequests: number;    // сколько просили стать mentor
    managementOffers: number;      // предложения management ролей
  };
  
  personalFit: {
    enjoymentLevel: number;        // 1-10, как понравилось
    stressLevel: number;           // 1-10, уровень стресса  
    futureMotivation: 'eager' | 'willing' | 'reluctant';
  };
  
  overallScore: number;            // 0-100 weighted score
  readiness: 'not_ready' | 'needs_development' | 'ready' | 'highly_ready';
}

async evaluateResponsibilityExperience(
  userExperience: ResponsibilityExperience
): Promise<ResponsibilityEvaluation> {
  
  // Results weight: 40%
  let resultsScore = 0;
  if (userExperience.results.projectsDelivered > 0) resultsScore += 25;
  if (userExperience.results.budgetPerformance !== 'over') resultsScore += 25;
  if (userExperience.results.teamSatisfactionScore >= 7) resultsScore += 25;
  if (userExperience.results.stakeholderFeedback === 'positive') resultsScore += 25;
  
  // Recognition weight: 30%  
  let recognitionScore = 0;
  if (userExperience.recognition.formalAwards) recognitionScore += 33;
  recognitionScore += Math.min(33, userExperience.recognition.mentorshipRequests * 10);
  recognitionScore += Math.min(34, userExperience.recognition.managementOffers * 15);
  
  // Personal Fit weight: 30%
  let personalScore = (
    userExperience.personalFit.enjoymentLevel * 5 +  
    (10 - userExperience.personalFit.stressLevel) * 3 +
    (userExperience.personalFit.futureMotivation === 'eager' ? 25 : 
     userExperience.personalFit.futureMotivation === 'willing' ? 15 : 0)
  );
  
  const overallScore = resultsScore * 0.4 + recognitionScore * 0.3 + personalScore * 0.3;
  
  return {
    overallScore,
    readiness: overallScore >= 75 ? 'highly_ready' : 
               overallScore >= 60 ? 'ready' :
               overallScore >= 40 ? 'needs_development' : 'not_ready'
  };
}
```

### **🔄 Основная идея: Последовательные оси развития**

```yaml
Три оси карьерного роста:
1. ШИРИНА: Рост по доменной области в ширину (охват разных частей проекта)
2. ГЛУБИНА: Рост по доменной области в глубину (повышение грейда/сложности)
3. ВЕРТИКАЛЬ: Вертикальный рост (управление людьми, влияние)

Правило последовательности:
- Джуниор не может расти по вертикали напрямую
- Сначала ОБЯЗАТЕЛЬНО ширина (для прохождения ИС)  
- После освоения ширины: выбор между глубиной или вертикалью
- Развилка после достижения Senior уровня
```

### **📈 Логика карьерного развития:**

#### **Этап 1: ШИРИНА (обязательный для всех)**
```yaml
Цель: Пройти испытательный срок
Описание: Освоить выполнение задач своего грейда в любой части проекта
Результат: Junior → Middle, универсальность в рамках своего уровня
Риск: Застрять в роли "вечного джуниора" на простых задачах по всему проекту
```

#### **Этап 2: РАЗВИЛКА (после освоения ширины)**
```yaml
Путь A: ГЛУБИНА (IC Track)
- Middle → Senior → Tech Lead → Principal Engineer → Chief Architect
- Фокус: Повышение сложности технических задач
- Подходит: Тем, кто любит решать сложные технические проблемы

Путь B: ВЕРТИКАЛЬ (Management Track)  
- Senior → Team Lead → Engineering Manager → Technical Director
- Фокус: Управление людьми и процессами
- Подходит: Тем, кто готов нести ответственность за результаты команды
```

### **🎯 Алгоритм определения целевой роли через WayMates:**

#### **1. Выявление склонностей через пользовательские истории:**
```yaml
Вместо прямого вопроса "Кем хотите стать?"
Анализируем истории пользователя на предмет:

Склонность к глубине:
- "Мне нравится разбираться в сложных технических задачах"
- "Часто погружаюсь в детали архитектуры"
- "Коллеги спрашивают у меня технические советы"

Склонность к вертикали:
- "Часто помогаю коллегам организовать работу"  
- "Нравится планировать и координировать проекты"
- "Хочу влиять на продуктовые решения"

Неопределенность:
- Задаем дополнительные вопросы на основе обязанностей ролей
- Показываем реальные истории людей из обеих треков
```

#### **2. Валидация реалистичности цели:**
```yaml
Проверяем через аватаров:
- Есть ли люди с похожим стартовым контекстом, достигшие этой цели?
- Сколько времени им понадобилось?
- Какие промежуточные этапы они проходили?
- Были ли у них схожие ограничения/табу?

Если цель недостижима:
- Предлагаем промежуточные реалистичные цели
- Показываем альтернативные пути
- Корректируем временные ожидания
```

#### **3. Проверка "счастья" от достижения цели:**
```yaml
Анализируем истории аватаров:
- Косвенные признаки удовлетворенности из их рассказов
- Остались ли они в выбранном треке или сменили направление?
- Прямая оценка: "Оцените от 1 до 5, как вам нравится ваша текущая роль" 
  (спрашиваем после прохождения ИС в новой позиции)

Если низкое "счастье":
- Предупреждаем пользователя о возможных подводных камнях
- Показываем альтернативные пути развития
- Предлагаем пообщаться с "несчастными" в этой роли
```

### **💡 Ключевая проблема, которую решаем:**

#### **Проблема:** Неосознанный выбор карьерной цели
```yaml
Типичные ошибки пользователей:
❌ "Хочу стать тимлидом" (не понимая, что это значит)
❌ "Хочу больше зарабатывать" (без понимания, как этого достичь)  
❌ "Все идут в менеджмент, и я пойду" (следование за толпой)

WayMates решение:
✅ Показываем реальные обязанности через истории аватаров
✅ Демонстрируем альтернативные пути достижения финансовых целей
✅ Предупреждаем о подводных камнях на основе опыта других
✅ Помогаем выбрать путь, соответствующий личным склонностям
```

```yaml
4. Валидация реалистичности цели через статистику успеха

6. Построение пошагового плана через промежуточные цели
```

```typescript
class CareerPathEngine {
  // Определение готовности к смене оси
  assessAxisReadiness(userContext: UserContext): AxisRecommendation {
    const widthCoverage = this.calculateWidthCoverage(userContext);
    const depthLevel = this.assessDepthLevel(userContext);
    const verticalExperience = this.assessVerticalExp(userContext);
    
    if (widthCoverage < 70) {
      return { recommendedAxis: 'width', reason: 'Завершите освоение ширины для стабильности' };
    }
    
    if (depthLevel < 'senior' && userContext.prefersTechnical) {
      return { recommendedAxis: 'depth', reason: 'Ваш профиль подходит для технического трека' };
    }
    
    if (verticalExperience > 0 && userContext.prefersLeadership) {
      return { recommendedAxis: 'vertical', reason: 'Есть опыт управления, можно развивать' };
    }
    
    return { recommendedAxis: 'choice', reason: 'Готовы выбирать между глубиной и вертикалью' };
  }
  
  // Поиск успешных путей
  findSuccessfulPaths(fromContext: UserContext, toRole: string): PathRecommendation {
    const similarAvatars = this.findSimilarStartingContexts(fromContext);
    const successful = similarAvatars.filter(a => a.finalRole === toRole);
    
    return {
      pathExists: successful.length > 0,
      averageTime: this.calculateAverageTime(successful),
      commonSteps: this.findCommonIntermediateSteps(successful),
      successRate: successful.length / similarAvatars.length,
      riskFactors: this.identifyCommonRisks(successful)
    };
  }
}
```
