## Рефлексия

### Как делать правильно
- **Семантические описания в промптах:** ЧТО + ПОЧЕМУ, не примеры фраз (guidelines.md §1.1)
- **Глубокий code review перед рефакторингом:** Инвентаризация всех проблем → task file → plan
- **Sequential thinking для архитектурных вопросов:** Структурирует мысли

### Как делать неправильно
- **Примеры фраз в промптах:** LLM начинает pattern matching вместо понимания
- **enrichResponse как async wrapper:** Грязная архитектура, лучше инжектить данные в NlpFormatter
- **Дублирование state полей:** currentSearchParams + appliedFilters с почти идентичными данными

### Инсайты

1. **Response builders должны возвращать только dynamic state data:**
   - Убрать options (статика по phase)
   - Убрать availableFilters (статический словарь)
   - Убрать currentFilters (статический enum)

2. **NlpFormatter должен знать статику сам:**
   - Inject DictionariesCache
   - Знать options по phase
   - Знать contextFields enum

3. **Flat state OK для LangGraph:**
   - Discriminated union не поддерживается
   - Проблема в naming, не в structure

### Наставления от пользователя

1. **"Промпты не должны быть забиты гвоздями"** → Семантические описания
2. **"Минимум 90%+ уверенности перед ответом"** → Читать код, проверять git blame
3. **"harder thinking"** → Sequential thinking для сложных вопросов
4. **"Создай файл задачи"** → Структурированный task file важнее устного описания
