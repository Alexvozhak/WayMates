# 6 месяцев с Claude Code: методология соло-разработки

**Контекст:** 6 месяцев, 14ч/день, один разработчик → полноценный продукт (WayMates)
**Инструмент:** Claude Code CLI как "second brain"

---

## 1. Философия: от хаоса к системе

### Проблема

LLM может быть уверен в своих знаниях и полностью провалить задачу.

> 💡 **Из практики:** Claude был уверен на 95%. Но он понимал только код и архитектуру — не понимал ЗАЧЕМ мы делаем задачу. Слепо выполнял план.

### Решение: три критерия готовности (90%+)

| Критерий | Что проверяет | Вопрос |
|----------|---------------|--------|
| Код/архитектура | Структура проекта, паттерны | ГДЕ и КАК менять? |
| Бизнес-логика | Правила, сценарии, ограничения | ЧТО должно работать? |
| Смысл задачи | Контекст, цель, влияние | ЗАЧЕМ это нужно? |

**Правило:** Если любой критерий <90% — не начинать. Пусть читает код, документацию, спрашивает.

### Метафора

LLM — необузданный зверь с огромной силой, но без понимания границ. Задача — воспитать его, ввести в состояние "сверхразума", когда он понимает ЧТО, ГДЕ, КАК и ЗАЧЕМ.

## 2. Система накопления контекста

### Перед сессией: загрузка контекста

| Документ | Зачем |
|----------|-------|
| Архитектура проекта | Структура, паттерны, решения |
| Бизнес-логика | Правила, сценарии, edge cases |
| Текущая задача | Что делаем, зачем, критерии успеха |
| eslint.config | Стиль кода, ограничения |
| package.json | Зависимости, скрипты |

### После сессии: рефлексия

Вопросы для Claude:
1. Какие инсайты по архитектуре?
2. Какие инсайты по бизнес-логике?
3. Где ошибся? Какая первопричина?

Ответы → три документа:
- **Архитектура** — технические решения
- **Бизнес-логика** — правила, edge cases
- **Guidelines** — паттерны ошибок ("ошибка → правило")

## 3. Инфраструктура дисциплины

### Проблема

"Пиши качественный код" — слишком абстрактно. Нужны конкретные, автоматически проверяемые правила.

### Решение

| Инструмент | Что делает |
|------------|------------|
| **ESLint (строгий)** | max-depth: 2, complexity: 8, max-lines: 60, no `any`/`as` |
| **Knip + sonarjs** | Дублирование, неиспользуемый код |
| **Husky + lint-staged** | Pre-commit проверки |

> 💡 **Важно:** Claude любит "не помнить", что код был другим до него. Pre-commit хуки ловят проблемы сразу, а не через 10-20 коммитов.

### Конфигурация Claude Code

| Настройка | Зачем |
|-----------|-------|
| `auto-compact: off` | Контроль над контекстным окном |
| Статус бар с токенами | Видеть реальный остаток (~30k токенов бонус) |

## 4. Power-user техники

### Rewind

Откат сессии к сообщению БЕЗ отката изменений в файлах.

**Сценарий 1: Берсерк x10**
```
План: 10 задач, один контекст
1. Выполнить задачу 1 → отчёт → сохранить
2. Откатить к началу
3. Вставить отчёт о задаче 1
4. "Теперь задача 2"
5. Повторить
```
Результат: 10-15 задач за одну сессию.

**Сценарий 2: Ветвление**
```
Возник вопрос → разбор в сессии → понял
├── Без артефакта: откатить, продолжить
└── С артефактом: отчёт → откатить → продолжить с новым пониманием
```

### Before-rewind

На 10-15% оставшегося окна:
- Краткий отчёт что сделали
- Что осталось
- Инсайты для следующих задач
- Обновления в документацию

### Accept-on-edit

> ⚠️ **Предупреждение:** Даже для проработанной задачи — не уходить от кассы. Каждый раз находился камень преткновения.

Включать только для малых, простых, согласованных задач.

### Субагенты

| Когда использовать | Когда НЕ использовать |
|-------------------|----------------------|
| Ресёрч (context7, websearch) | Code review |
| Проверка готовности к интеграции | Планирование |
| Изучение best practices | Любое, где нужен контроль |

### Инструменты

| Вместо | Использовать | Почему |
|--------|--------------|--------|
| `sed` | `mcp__filesystem__edit_file` | 2/3 sed = коллапс |
| Много `Read` | `mcp__filesystem__read_multiple_files` | Batch эффективнее |

## 5. Принципы в промптах

### Ключевые фразы

| Фраза | Эффект |
|-------|--------|
| "Соблюдай SRP" | Каждый метод/класс — своя зона ответственности |
| "Не пытайся угодить" | Признаётся в неуверенности, спрашивает |
| "Пиши консистентный код" | Использует grep, следует существующим паттернам |
| "Принцип Парето" | 20% усилий → 80% результата, без overengineering |
| "Не изобретай велосипед" | Сначала ресёрч библиотек |
| "Только бизнес-ценные тесты" | Без фиктивных проверок |
| "Fail fast" | Ошибка на входе, не defensive coding |

> 💡 **Пример "не изобретай велосипед":** Батчинг сообщений. Самопал: 100 строк → первая либа: 50 строк → promise-batcher: 15 строк.

### Обучение новым инструментам

```
1. Бизнес-задача → 2. context7 + websearch → 3. Документ → 4. Прикреплять каждую сессию
```

Ошибка: сразу писать бизнес-код. Сначала — обучить на примерах.

## 6. Универсальные правила

Формат: ошибка → правило.

### Процесс работы

| Ошибка | Правило |
|--------|---------|
| Edit без объяснения | 90%+ уверенность → Проблема → Как сейчас → Как будет → Ждать "ок" |
| Додумываю бизнес | Бизнес спрашивать, техническое проверять по коду |
| "Файл не найден" | Glob по имени перед тем как сдаться |
| Считаю исправленным | Визуальная верификация обязательна |

### Код

| Ошибка | Правило |
|--------|---------|
| Fallbacks "на всякий" | YAGNI — сложность при доказанной необходимости |
| Дублирование "потом" | DRY сразу |
| `as Type` | Zod `.parse()` или typeguard |
| Ручной cleanup | `lint:fix` |

### Отладка

| Ошибка | Правило |
|--------|---------|
| Искал не там | Debug от конца к началу |
| Долго гадал | Logging на КАЖДОМ этапе |
| Debug всего сразу | Убирать части по одной |

### Коммуникация

| Ошибка | Правило |
|--------|---------|
| Подтверждаю ожидания | Честный анализ > угодничество |
| Одно решение | Контекст → варианты → рекомендация → % уверенности |

### Разрешения

**Без подтверждения:**
- Читать код, логи
- `lint:fix`, `tsc --noEmit`
- MCP read queries
- context7, websearch

**С подтверждением:**
- Изменения в коде
- Удаление данных
- Перезапуск инфры
- Архитектурные решения

## Главное правило

> **Приходи не с проблемами, а с вариантами решений.**

Критерии оценки:
- Честность (перед пользователями)
- Простота (LOC, файлы)
- Чистота архитектуры
- Рациональность (Парето)
- Best practices

Рекомендация + альтернативы + сравнение + % уверенности.
