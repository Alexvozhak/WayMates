# WayMates: Хранение и сопоставление маршрутов

**Дата:** 20 сентября 2025  
**Статус:** Архитектурные решения  
**Тема:** Как хранить и сопоставлять маршруты для поиска когорт и аватаров

---

## 🎯 Ключевые решения

### **1. Архитектура поиска**
- **Сначала когорта, потом аватары** — логично следует определению
- **Когорта** = пользователи, у которых когда‑то был контекст, максимально похожий на наш текущий; для них используем их самый похожий контекст (прошлый или текущий), для нас — наш актуальный
- **Аватары** = пользователи из когорты, достигшие целевого контекста (в профиле есть и наш текущий, и наш целевой контексты)

### **2. Базовые фильтры (MVP)**
1. **Роль** — точное совпадение (позже допускаем семейство/смежные)
2. **Индустрия** — точное совпадение (позже расширяем до макросектора/любой)
3. **Домены** — требуется минимум 1 общий домен
4. **Опыт в роли** — разница не более ±1 года
5. **Навыки** — считаем пересечение всех навыков текущего контекста, используем и количество, и долю совпадений (coverage)

### **3. Адаптивная логика (ослабление/ужесточение)**
- **Цель:** найти минимум 5 аватаров, максимум 100 результатов
- **Если мало аватаров (<5):**
  1) Снизить minCoverage: 0.8 → 0.6 → 0.4 → 0.0
  2) Ослабить опыт: ±1 → ±2 → без ограничения
  3) Снять требование по домену (если всё ещё мало)
  4) Расширить индустрию: exact → macro → any
  5) Смягчить роль: exact → family → adjacent
- **Если слишком много (>100):**
  ужесточать в обратном порядке и/или поднять minCoverage

### **4. Ранжирование (MVP)**
- **Сортировка:**
  1) matchedSkills (количество общих навыков)
  2) coverage = matchedSkills / size(userSkills)
  3) domainMatch (1/0)
  4) expDelta = |разница по стажу в роли|
- **Нормализация навыков:** словарь синонимов; категории (языки, фреймворки, библиотеки) — ввести веса позже

### **5. Интеграция с тропами аватаров**
- **Тропы аватаров** - проверенные пути саморазвития
- **Маршрут** - тропы аватаров для построения пути развития
- **Полнота опыта** - аватары с полными тропами приоритетнее

**Идея:** Пользователю без сформулированной цели важно выяснить, как и что он может развивать.
**Все варианты**
- **A)** Показываем все возможные переходы из текущего контекста
- **B)** Показываем только "популярные" переходы (частота в когорте)
- **C)** Показываем "легкие" переходы (низкая сложность, короткое время)

## ⚙️ Технические заметки (MVP)

- Источник правды: только текущие контексты пользователей и аватаров; история как мягкий фолбек допускается позже.
- Порог/лимиты: minAvatars = 5, maxResults = 100, minCoverage ступени = [0.8, 0.6, 0.4, 0.0].
- Тай-брейкеры: domainMatch, expDelta, далее отраслевые/кастомные веса.
- Нормализация: словарь синонимов навыков; привести регистр/канонические названия.
- Логи и калибровка: сохранять распределения coverage/expDelta и причины ослаблений для настройки порогов.
- Fallback (по необходимости): GraphCypherQAChain только read-only и с пост‑фильтрацией по правилам выше.
- Политика выполнения (MVP): запись (validate/normalize/persist) и поиск когорты/аватаров — через neo4j-driver; прочие запросы — fallback через GraphCypherQAChain (read-only) с пост‑фильтрацией. В prod — под feature‑flag.
