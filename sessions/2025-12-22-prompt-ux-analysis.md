# Сессия: Анализ UX промптов и унификация NLP архитектуры

**Дата:** 2025-12-22
**Задача:** Анализ промптов в langGraph — раскрытие возможностей схем пользователю

---

## Фаза 1: Исследование проблемы

### Что сделано

1. **Проанализированы все промпты** в `src/facade/langGraph/*/prompts.ts`
2. **Выявлена системная проблема:** промпты написаны для LLM ("как извлекать"), а не для пользователя ("что можно указать")
3. **Инвентаризация скрытых возможностей:**
   - Cold-Start: languages B2+, citizenships, educationLevel, salary range — не спрашиваем
   - Search: desired/undesired mode, excludedReasons, recencyThresholdMonths — не раскрываем
   - Trails: ratings (1-5), feedback, cost — не собираем

### Ключевые находки

- **reasons.json** уже имеет descriptions в Neo4j, но они не используются в runtime
- Zod `.describe()` попадает в JSON Schema → LLM видит при structured output
- Presenters форматируют JSON через LLM, а не просто переводят

## Фаза 2: Архитектурное открытие

### Обнаружена inconsistency

| Тип response | Facade | Client |
|--------------|--------|--------|
| **SystemMessage** | Full English NLP | Только перевод |
| **Graph responses** | JSON + короткий message | LLM форматирует |

### Эталонные коммиты

- `e920bcb` — hints → client expands
- `476a451` — **full NLP → client translates** (финальный паттерн)

### Итог

Решено создать **FEAT-037** для унификации архитектуры:
- Все Graph responses → full NLP в Facade
- Presenters → только перевод (как SystemMessagePresenter)
- Оценка: ~400 LOC, ~36 NLP шаблонов

## Рефлексия

### Наставления от пользователя

| Наставление | Контекст | Вывод |
|-------------|----------|-------|
| **90%+ уверенность** | Выдумал содержимое `reasons.json` | Читать файл ПЕРЕД утверждениями |
| **Не давать дословные примеры** | Предложил русские фразы в промпты | Семантические описания: ЧТО + ПОЧЕМУ, не КАК |
| **Понимать архитектуру** | Не знал что Presenters форматируют, а не переводят | Читать код, не предполагать |
| **Не дублировать** | Хотел descriptions в промпт + в response | Один источник истины |

### Инсайты

1. **Guidelines 1.1** — примеры в промптах = pattern matching trap. LLM копирует вместо понимания
2. **Client-agnostic** — response должен быть self-contained, другой клиент не знает про отдельные ручки
3. **Inconsistency дорого** — два паттерна в одном проекте = путаница и ошибки

### Как делать правильно

- Читать код перед утверждениями о нём
- Проверять git history для понимания архитектурных решений
- Задавать уточняющие вопросы вместо додумывания
- Один источник истины для данных

### Как делать неправильно

- Выдумывать содержимое файлов
- Давать конкретные фразы в промпты (pattern matching)
- Предлагать решения без понимания текущей архитектуры
- Дублировать данные в разных местах
