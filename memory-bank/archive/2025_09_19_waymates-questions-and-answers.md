## 🔥 КРИТИЧЕСКИ ВАЖНЫЕ НЕРЕШЕННЫЕ

### 1. Драйвер Neo4j или MCP? РЕШЕН
**Вопрос:** neo4j-driver или MCP-neo4j?

**Решение (MVP):** используем `neo4j-driver` как основной путь (ingest, поиск, ранжирование). Fallback — `GraphCypherQAChain` (read-only) с ограждениями; `mcp-neo4j` — только для R&D/инспекции.

- **Основной путь:** все критичные операции через `neo4j-driver` (Bolt), контроль транзакций, типобезопасность TS.
- **Fallback:** временно покрывает «длинный хвост» запросов до появления TS‑ручек; ограничения: низкая температура, timeout, LIMIT ≤ 100, запрет write/процедур; пост‑фильтрация по must‑have правилам.
- **Стратегия MVP:** fallback включён; по частоте запросов закрепляем ручки в TS поверх `neo4j-driver`.

### 2. Адаптация алгоритма поиска РЕШЕН
**Вопрос:** В каком порядке ослаблять фильтры при малом количестве аватаров?

**Варианты ответов:**
- A) Опыт → Домены → Навыки → Индустрия → Роль
- B) Домены → Опыт → Навыки → Индустрия → Роль  
- C) Настраиваемый порядок для разных типов пользователей

**Решение (MVP):**
- Базовый матч: сравниваем текущий контекст пользователя с контекстами кандидатов.
- Фильтры по умолчанию: роль = exact; индустрия = exact; домены ≥1 общий; опыт ±1 год.
- Ранжирование: matchedSkills → coverage (matched/все твои навыки) → domainMatch → |expDelta|.
- Ослабление при дефиците (<5 результатов):
  1) minCoverage: 0.8 → 0.6 → 0.4 → 0.0
  2) опыт: ±1 → ±2 → без ограничения
  3) домены: снять требование
  4) индустрия: exact → macro → any
  5) роль: exact → family → adjacent
- При избытке (>100 результатов): ужесточать в обратном порядке и/или повышать minCoverage.
- Нормализация навыков: словарь синонимов; позже — веса категорий (языки > фреймворки > библиотеки) и учёт рецентности.

## ✅ РЕШЕННЫЕ

### 10. Система анонимизации
**Вопрос:** Как обеспечить анонимность рассказчиков при сохранении полезности данных?

**Решение:** Удаляем все персональные данные, оставляем только контекст и тропы

### 11. Автоматизация сбора троп
**Решение:** Платформа реализована как MCP-сервер, который можно подключить локально для прямого вливания историй (без Telegram). Мы (как разработчики) можем самостоятельно добавлять автоматизированный скрабинг сайтов или импорт архивных статей/историй, если они подходят по сути (решение принимает разработчик платформы).

### 12. Проблема холодного старта
**Вопрос:** Что делать, когда ещё нет Контекстов, Троп и тем более Маршрутов у первых пользователей?

**Решение:**
1. На MVP производим только накопление Контекстов, Троп, Маршрутов
2. Скрапинг и импорт в проект чужих историй, пытаемся их адаптировать под наши Контексты, Тропы, Маршруты
3. Проект как MCP — любая платформа может импортировать свои истории (мы у себя их проверяем)

### 13. Градация фич по уровню данных
**Идея:** Разделить фичи на уровни в зависимости от того, какие данные есть у пользователя.

**Уровни:**
- **Уровень 1:** Только профиль (контекст) → базовые рекомендации
- **Уровень 2:** + тропы → персонализированные маршруты
- **Уровень 3:** + цель → точное ведение по маршруту
