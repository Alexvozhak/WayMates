## Рефлексия

### Как делать правильно

- **Объяснять концепции на примерах кода** — абстрактные объяснения типа "публикуем только типы" непонятны без конкретного кода
- **Показывать "до/после"** — сразу видна разница и ценность изменения
- **Спрашивать уточняющие вопросы** — "что именно скрываем: только cypher или весь core?"

### Как делать неправильно

- **Усложнять без необходимости** — предлагал npm packages для типов, когда достаточно простого interface
- **Объяснять абстрактно** — "type не содержит код" без примера кода непонятно
- **Предполагать понимание** — термины вроде "re-export типов" требуют объяснения

### Инсайты

1. **Interface как контракт между репо** — простой паттерн для разделения кодовых баз без npm packages
2. **Все типы уже в shared** — роутеры используют схемы из `shared/schemas.ts`, что упрощает split
3. **`.client` getter** — legacy паттерн, который использовался для прямого доступа к tRPC; теперь заменяется на typed methods
