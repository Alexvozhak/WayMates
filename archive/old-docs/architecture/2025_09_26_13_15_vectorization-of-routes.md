# Векторизация маршрутов в WayMates

Дата: 2025-09-26

## Проблема и возможности

### Сценарий использования
**Ситуация:** Пользователь имеет текущий контекст, нашли когорту, но нет четкой цели. Вопрос: "А есть ли что-нибудь из когорты кто добился примерно вот такого-такого-такого?"

**Текущий подход без векторизации:**
- Пользователь просматривает список всех маршрутов когорты вручную
- Нет семантического поиска по описаниям достижений
- Сложно сопоставить "размытый" запрос с конкретными результатами

**Предлагаемый подход с векторизацией:**
- Векторизуем нормализованные "эпиграфы" всех маршрутов когорты
- Пользователь задает вопрос в свободной форме
- Семантический поиск находит наиболее релевантные маршруты
- AI получает больше контекста для качественных рекомендаций

## Что векторизовать

### Вариант A: Нормализованный эпиграф маршрута
```typescript
interface RouteEpigraph {
  user_id: string;
  route_summary: string;        // "Frontend Junior → Senior Developer"
  achievement_description: string; // "Перешел в Booking.com, повысил зарплату на 180%"
  timeline: string;             // "7 месяцев"
  context_tags: string[];       // ["frontend", "react", "amsterdam", "startup-to-corporate"]
  outcome_metrics: {            // Ключевые результаты
    salary_increase_percent?: number;
    new_role?: string;
    new_location?: string;
    new_grade?: string;
  }
}
```

### Вариант B: Полный контекстный след
```typescript
interface FullRouteContext {
  starting_context: ContextInput;  // Откуда начинал
  ending_context: ContextInput;    // Чего достиг  
  trail_summaries: string[];       // Краткие описания всех троп
  transformation_story: string;    // Повествование о переходе
}
```

## Примеры использования

### Пример 1: Размытый запрос пользователя
```
ПОЛЬЗОВАТЕЛЬ: "Хочу что-то связанное с менеджментом и работой в Европе"

БЕЗ ВЕКТОРИЗАЦИИ:
- Показать все маршруты когорты (50+ штук)
- Пользователь ручками ищет подходящие
- AI не понимает семантику запроса

С ВЕКТОРИЗАЦИЕЙ:
- Векторный поиск по эпиграфам: ["team lead", "project manager", "netherlands", "berlin"]  
- Топ-5 релевантных маршрутов с high cosine similarity
- AI: "Нашел 3 похожих пути: Михаил стал Team Lead в Амстердаме за 8 месяцев..."
```

### Пример 2: Поиск по outcome
```
ПОЛЬЗОВАТЕЛЬ: "Кто-то повышал зарплату больше чем в 2 раза?"

БЕЗ ВЕКТОРИЗАЦИИ:
- Нет способа искать по метрикам результата
- Нужно просматривать все профили вручную

С ВЕКТОРИЗАЦИЕЙ:
- Поиск по outcome_metrics: salary_increase_percent > 200%
- + семантический поиск по описаниям: "doubled salary", "200% increase"
- Результат: "Анна увеличила зарплату на 180% переходом в Spotify"
```

### Пример 3: Кейсы для AI рекомендаций

**AI без векторизации:**
```
"В когорте 47 человек. Вот список всех их профилей... [dump данных]
Выбери подходящий для пользователя."
```

**AI с векторизацией:**
```
"В когорте 47 человек. По семантическому поиску наиболее релевантные:

1. Михаил: Frontend Junior → Senior (similarity: 0.89)
   Эпиграф: "Перешел из стартапа в Booking.com через интенсивное изучение системного дизайна"
   
2. Анна: React Developer → Team Lead (similarity: 0.84)  
   Эпиграф: "Совместила техническое развитие с менеджментом команды в финтехе"
   
Рекомендую фокус на системном дизайне как у Михаила..."
```

## Технические детали

### Что векторизуем
- **Основной контент:** route_summary + achievement_description + transformation_story
- **Обогащенный контент:** + context_tags + outcome_metrics как дополнительные измерения

### Как считаем похожесть
- **Cosine Similarity** для семантической близости описаний
- **Weighted Distance** для объективных метрик (зарплата, сроки, локация)
- **Комбинированный скор:** 0.7 * cosine_sim + 0.3 * metrics_distance

### Где храним вектора
- **Вариант A:** Дополнительное поле `route_vector` в Neo4j узлах
- **Вариант B:** Отдельный Vector DB (Pinecone, Weaviate)
- **Вариант C:** Elasticsearch с vector search

### Обновление векторов
- **При создании маршрута:** автоматическая векторизация эпиграфа
- **При обновлении контекста:** ре-генерация вектора если изменился outcome
- **Batch update:** периодическое обновление всех векторов при улучшении модели

## Стоит ли векторизовать?

### ✅ Pros
1. **Семантический поиск** - находим релевантное по смыслу, а не точным словам
2. **AI-friendly** - лучше контекст для рекомендаций
3. **Гибкие запросы** - пользователь может спрашивать в свободной форме  
4. **Scalable** - с ростом базы маршрутов поиск останется быстрым

### ❌ Cons
1. **Complexity** - дополнительная инфраструктура и процессы
2. **Overhead** - векторизация при каждом обновлении маршрута
3. **Quality dependency** - результат зависит от качества описаний в эпиграфах
4. **Не universal** - не все запросы подходят для векторного поиска

### 🤔 Альтернативы
- **Тегирование** - структурированные теги вместо векторов
- **Full-text search** - Elasticsearch по описаниям
- **Фильтры + сортировки** - классический подход по структурированным полям

## Рекомендация для MVP

### ❌ Векторизация ОТЛОЖЕНА для MVP

**Причины отложения:**
- **Нарушение правила Парето:** 80% сложности для 20% пользы
- **Дублирование функций:** Граф + AI нормализация уже покрывают основные потребности
- **MVP фокус:** Сначала докажи ценность на структурированных данных
- **Упрощение:** Constraints покрывают 90% случаев без enum'ов

### ✅ Упрощенный подход для MVP
- **Граф + AI нормализация:** Структурированные данные через TypeBox схемы
- **Constraints фильтрация:** Время, бюджет, deadline через простые проверки
- **Scoring через веса:** Как в когорте, без категорий
- **Post-MVP:** Векторизация для семантического поиска после получения user feedback

## Вывод

**Векторизация маршрутов отложена до post-MVP.**

**Причины:**
- Граф + AI нормализация покрывают 80% потребностей
- Constraints решают 90% задач фильтрации
- Простой scoring через веса достаточен для MVP
- Векторизация добавляет сложность без пропорциональной пользы

**Рекомендация:** Сфокусироваться на графе и constraints, векторизацию добавить после получения user feedback и доказательства ценности базового подхода.

**Приоритет:** Отложен - не нужен для MVP.
