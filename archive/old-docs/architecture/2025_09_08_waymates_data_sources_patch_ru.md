# Patch к спецификации: источники данных (ЕС/США/UK), ESCO → LightRAG, роль ClickHouse

_Этот патч дополняет файл **waymates_tempo_spec_ru.md** и фиксирует решения для MVP по словарям навыков и хранилищам._

---

## TL;DR (что меняем прямо сейчас)
- **Рынок/лексика:** ориентируемся на **ЕС** (без US-набора на старте).
- **Источник словаря:** берём **ESCO** (skills + hierarchy + alt labels). Формат выгрузки: **classification / CSV / en** (+ru при необходимости).
- **Хранилище графа:** загружаем ESCO в **LightRAG** как **доменно заданный KG** (_GraphStorage под капотом — вероятнее всего **Neo4j** из docker-compose; уточняем_).
- **Аналитика времени:** **ClickHouse** используем **не для всего ESCO**, а только как **`skills_dim` + наши витрины** (темпы/сессии/«обычно/с запасом»).
- **Временной бейзлайн:** **не** берём O*NET/SVP (US) на старте; часы выражаем по **ECTS** (EU-норма 25–30 ч/кредит) и быстро замещаем своими фактами.

---

## 1) Термины и источники (структурно)

### ЕС (берём сейчас)
- **ESCO** — открытая классификация **навыков** и **иерархии**, есть синонимы и метки переносимости. Даёт **узлы/рёбра** для нашего графа троп.
- **e-CF (EN 16234-1)** — каркас **ИКТ-компетенций** с уровнями. Для MVP **опционально** (можно использовать как слой группировок/“рамок” троп позже).
- **EQF** — рамка уровней **квалификации** (1–8). Для MVP **опционально**, если не маркируем тропы уровнями.
- **ECTS / Europass (ELM)** — EU-способ выразить **нагрузку в часах/кредитах**. Используем как **прокси часов** для троп в отсутствие своей статистики.

### США / UK (пока не берём в MVP)
- **O*NET / SOC / SVP (US)** — даёт «время подготовки по профессии», но мы готовимся **по тропам/навыкам**, не по роли; переносим на позже.
- **SFIA (UK/глоб.)** — уровни ответственности 1–7; полезно для глубины, **но не критично** на старте.

---

## 2) ESCO: как именно выгружаем и что загружаем

**Формат выгрузки:** `classification / csv / en` (+`ru` по желанию).  
**Минимальный набор CSV для MVP-графа:**
- `skills.csv` → узлы `:Skill {escoId, label_en, label_ru?, type (skill|knowledge)}`
- `skills_hierarchy.csv` → рёбра `(:Skill)-[:BROADER_OF]->(:Skill)`
- `skills_alt_labels.csv` → синонимы (сохраняем как массив свойства или отдельные `:Alias`)

> Профессии (`occupations*`) и связи с навыками можно **не** грузить на старте — работаем через **тропы** (skill-tracks) без привязки к ролям.

---

## 3) Куда именно кладём ESCO и зачем

### LightRAG (граф-ядро для RAG)
- Загружаем ESCO как **custom KG** (узлы/рёбра) → **GraphStorage**.
- **Под капотом:** по умолчанию **Neo4j** (в docker-compose LightRAG обычно поднимает `neo4j` + `chromadb`). **Статус: уточнить конфиг** и явно зафиксировать драйвер графа.
- Получаем обходы графа, объяснимые цепочки («соседние навыки / родительские кластеры») и гибридный ретрив вместе с эмбеддингами.

### ClickHouse (аналитика фактов)
- Не дублируем весь ESCO; ведём **минимальный справочник**:
  - `skills_dim(skill_id, label_en, label_ru, type)`
- Факты и витрины (пример):
  - `study_sessions` (сырые сессии: user, skill, дата, часы, пауза, источник)
  - `skill_completions` (закрытия: фактические часы/темп/дельта)
  - `skill_tempo_summary` (витрина: «обычно/с запасом», эффективность, n)
  - `user_factors` (витрина: множитель скорости)
- Зачем: быстрые квантили/медианы/срезы; соединяем факты с `skills_dim` для человекочитаемых отчётов и API-ответов.

---

## 4) Время/нагрузка для троп (EU-логика)
- На старте даём **нагрузку троп** в **ECTS/часах** (например, 2 ECTS ≈ 50–60 ч).
- Персонализируем срок в неделях через наш **темпо-модуль** («обычно / с запасом»).
- По мере накопления фактов обновляем витрины и **замещаем ECTS-оценки** реальными числами.

## 6) Ближайшие шаги (MVP-план на 1–2 дня)
1) Выгрузить ESCO (`classification/csv/en`), подготовить 3 CSV (skills / hierarchy / alt_labels).  
2) Поднять **LightRAG** в Docker; включить граф-бэкенд (**Neo4j**, если идём по умолчанию).  
3) Импортировать ESCO → LightRAG KG (скрипт конвертации CSV → nodes/edges).  
4) Завести в **ClickHouse**:
   - `skills_dim` (ID + labels + type),
   - `study_sessions`, `skill_completions`,
   - простую витрину `skill_tempo_summary` (медианы «обычно», ×1.5 «с запасом» до накопления данных).
5) Проткнуть **/estimate** в API: граф-нормализация термина → расчёт срока по темпо-логике с учётом `skills_dim`.

---

## 7) Решение «почему не только LightRAG»
LightRAG даёт **граф и поиск** (идеально для троп и объяснимости), но **не** предназначен для **OLAP-аналитики** по событиям/срокам. Поэтому:
- **LightRAG+GRAPH** = доменная карта (навигация/ретрив),
- **ClickHouse** = факты/агрегаты по времени и темпу.
