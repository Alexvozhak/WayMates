  План: Telegram Bot Integration

  Ключевой принцип

  Telegram Bot = тонкий клиент (LLM-адаптер NLP↔JSON)
  Facade = вся бизнес-логика + state machine

  - Transport: stdio (MCP-Use spawn Facade subprocess)
  - Framework: PoC обоих (grammY + Telegraf), выбор по TypeScript качеству
  - STT: OpenAI Whisper
  - Auth: Token-based linking (symmetric registration)

  6 этапов реализации

  1. PoC frameworks (2-3 дня) - сравнение grammY vs Telegraf
  2. Package setup - структура packages/telegram-bot/
  3. MCP Client - MCP-Use stdio integration
  4. Conversations - cold_start flow + InlineKeyboard
  5. Voice - OpenAI Whisper STT
  6. Auth - Token linking
  7. Testing

  Timeline: ~10-13 дней

     Исследование: LLM как адаптер

     Архитектура

     User: "Привет, хочу рассказать историю"
              ↓
     Telegram LLM (Gemini) с System Prompt:
       - Понимает intent
       - Решает какой MCP tool вызвать
       - Формирует params
              ↓
     MCPAgent.run() → cold_start(message, sessionId)
              ↓
     Response от Facade (phase, message, data)
              ↓
     LLM форматирует для пользователя + InlineKeyboard

     System Prompt для Telegram LLM

     const TELEGRAM_SYSTEM_PROMPT = `
     Ты — карьерный ассистент WayMates в Telegram.

     ДОСТУПНЫЕ ИНСТРУМЕНТЫ:
     - cold_start: Сбор карьерной истории (multi-turn workflow)
     - search_careers: Поиск путей трансформации
     - get_story: Показать историю пользователя
     - set_goal / get_goal: Управление карьерными целями

     ПРАВИЛА:
     1. Всегда используй sessionId из контекста
     2. При получении phase=awaiting_*_confirmation — предложи кнопки
     3. При edit запросе — передай corrections в message
     4. Форматируй ответы коротко (Telegram ограничение)

     ФАЗЫ cold_start:
     - story_gathering → "Расскажите историю"
     - awaiting_plan_confirmation → показать план + кнопки
     - awaiting_context_confirmation → показать context + кнопки
     - awaiting_final_confirmation → итоговое подтверждение
     - saved → успех
     - failed → ошибка
     `

     grammY InlineKeyboard

     import { Bot, InlineKeyboard } from 'grammy'

     const bot = new Bot<Context>(process.env.TELEGRAM_TOKEN!)

     // Создание клавиатуры
     const keyboard = new InlineKeyboard()
       .text("✅ Подтвердить", "decision:confirm")
       .text("✏️ Редактировать", "decision:edit")
       .row()
       .text("❌ Отменить", "decision:cancel")

     await ctx.reply("Подтвердите план:", { reply_markup: keyboard })

     // Обработка callback
     bot.callbackQuery(/^decision:(.+)$/, async (ctx) => {
       const action = ctx.match[1]  // "confirm" | "edit" | "cancel"
       await ctx.answerCallbackQuery()  // Убрать loading

       // Передать в MCPAgent
       const result = await agent.run(`Пользователь выбрал: ${action}`)
     })

     Telegraf InlineKeyboard

     import { Telegraf, Markup } from 'telegraf'

     const bot = new Telegraf<Context>(process.env.TELEGRAM_TOKEN!)

     // Создание клавиатуры
     const keyboard = Markup.inlineKeyboard([
       Markup.button.callback('✅ Подтвердить', 'decision:confirm'),
       Markup.button.callback('✏️ Редактировать', 'decision:edit'),
       Markup.button.callback('❌ Отменить', 'decision:cancel'),
     ])

     await ctx.reply('Подтвердите план:', keyboard)

     // Обработка callback
     bot.action(/^decision:(.+)$/, async (ctx) => {
       const action = ctx.match[1]
       await ctx.answerCbQuery()

       const result = await agent.run(`Пользователь выбрал: ${action}`)
     })

     Сравнение TypeScript качества

     | Аспект         | grammY                    | Telegraf                
     |
     |----------------|---------------------------|-------------------------
     |
     | ctx типизация  | ctx.match типизирован     | ctx.match as unknown[]  
     |
     | InlineKeyboard | Fluent API с типами       | Markup static methods   
     |
     | Middleware     | Generic C extends Context | Менее строгая типизация 
     |
     | callbackQuery  | bot.callbackQuery()       | bot.action()            
     |
     | Error types    | BotError с контекстом     | Generic Error           
     |

     Вывод: grammY лучше для TypeScript проекта

     Этап 4: Voice Support (OpenAI Whisper)

     Implementation

     // src/voice/openai-whisper.ts
     import OpenAI from 'openai';

     const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

     export async function transcribeVoice(fileBuffer: Buffer): 
     Promise<string> {
       const transcription = await openai.audio.transcriptions.create({
         file: new File([fileBuffer], 'voice.ogg', { type: 'audio/ogg' }),
         model: 'whisper-1',
         language: 'ru',  // или автодетект
       });
       return transcription.text;
     }

     Mitigation strategies (предложения)

     R1/R2: Agent per user

     // ВАРИАНТ A: Один shared MCPClient, отдельный agent per message 
     (stateless)
     const client = MCPClient.fromDict(...)  // shared
     const agent = new MCPAgent({ llm, client, memoryEnabled: false })
     // Memory вручную: Redis key = telegram:userId → conversation history

     // ВАРИАНТ B: Agent pool с user isolation
     const agents = new Map<number, MCPAgent>()  // telegramUserId → agent
     function getAgent(userId: number) {
       if (!agents.has(userId)) {
         agents.set(userId, new MCPAgent({ llm, client, memoryEnabled: true 
     }))
       }
       return agents.get(userId)!
     }
     // Риск: memory leak при многих users → нужен TTL eviction

     R3: sessionId scheme

     // Telegram userId → MCP sessionId (deterministic)
     function getMcpSessionId(telegramUserId: number): string {
       return `telegram:${telegramUserId}`  // или UUID v5 если нужна 
     privacy
     }

     // Facade использует sessionId для PostgreSQL checkpoint lookup
     // Одинаковый sessionId = resume предыдущего workflow

     R4: Subprocess recovery

     // MCP-Use должен иметь reconnect logic
     // Если нет — wrapper с retry:
     async function callToolSafe(tool: string, params: object) {
       try {
         return await client.callTool(tool, params)
       } catch (e) {
         if (isConnectionError(e)) {
           await client.reconnect()  // если есть
           return await client.callTool(tool, params)
         }
         throw e
       }
     }

● Пагинация в Telegram

  Telegram лимит: 4096 символов на сообщение.

  Как работает:
  function splitMessage(text: string, maxLength = 4000): string[] {
    if (text.length <= maxLength) return [text];

    const parts: string[] = [];
    let remaining = text;

    while (remaining.length > 0) {
      // Ищем последний перенос строки перед лимитом
      let splitIndex = remaining.lastIndexOf('\n', maxLength);
      if (splitIndex === -1) splitIndex = maxLength;

      parts.push(remaining.slice(0, splitIndex));
      remaining = remaining.slice(splitIndex).trimStart();
    }

    return parts;
  }

  // Использование
  const parts = splitMessage(longResponse);
  for (const part of parts) {
    await ctx.reply(part, { parse_mode: 'Markdown' });
  }

● Long-polling vs Webhook — подробное сравнение

  Long-polling (опрос)

  Как работает:
  Bot                              Telegram API
   │                                    │
   │─── GET /getUpdates ───────────────►│
   │                                    │ (ждёт до 30 сек)
   │◄────── [{update}, {update}] ──────│
   │                                    │
   │─── GET /getUpdates ───────────────►│
   │                                    │ ...

  Плюсы:
  - ✅ Не нужен публичный IP/домен
  - ✅ Не нужен HTTPS сертификат
  - ✅ Работает за NAT/firewall
  - ✅ Простая разработка локально

  Минусы:
  - ❌ Постоянное соединение = расход ресурсов
  - ❌ Задержка до 1-2 сек на получение update
  - ❌ Не масштабируется (один процесс)

  Когда использовать: Dev, тесты, маленькие боты (< 1000 users)

  Webhook (push-уведомления)

  Как работает:
  Telegram API                        Bot Server
       │                                   │
       │─── POST /webhook ────────────────►│
       │    {update}                       │
       │                                   │
       │─── POST /webhook ────────────────►│
       │    {update}                       │

  Плюсы:
  - ✅ Мгновенная доставка updates
  - ✅ Меньше ресурсов (нет polling loop)
  - ✅ Масштабируется (load balancer)
  - ✅ Production-ready

  Минусы:
  - ❌ Нужен публичный HTTPS endpoint
  - ❌ Нужен SSL сертификат (Let's Encrypt бесплатно)
  - ❌ Сложнее локальная разработка (нужен ngrok)

  Когда использовать: Production, > 1000 users
