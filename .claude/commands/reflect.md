# /reflect - Self-Reflection для улучшения документации

**Синтаксис**:
- `/reflect` - автоопределение модуля
- `/reflect cypher` - анализ Cypher-работы
- `/reflect qa` - анализ QA-работы
- `/reflect eslint` - анализ ESLint-работы
- `/reflect langgraph` - анализ LangGraph-работы

---

## Workflow

### 1. Определи модуль
Из последней работы или явно указан в команде.

### 2. Загрузи контекст
- **cypher**: `knowledge/cypher/router.md`, `cypher-rules.md`, `conventions.md`
- **qa**: `knowledge/qa/router.md` (future)
- **eslint**: `knowledge/eslint/router.md` (future)
- **langgraph**: `knowledge/langgraph/router.md` (future)

### 3. Самоанализ
- Что пошло не так при навигации?
- Какой информации не хватило?
- Повторялись ли известные ошибки?
- Как оптимизировать workflow?

### 4. Рекомендации
**Формат**: "Действие - Польза"

**Примеры**:
- "Добавить в FAQ 'Query медленный с OPTIONAL MATCH' - сократит debugging при повторе"
- "Обновить cypher-rules.md #12 с UNWIND примером - предотвратит syntax error"
- "Нет рекомендаций - документация покрыла все"

### 5. Покажи результат
```markdown
## 🔍 Self-Reflection: [module]

**Работа**: [краткое описание]

**Рекомендации**:
1. [Действие] - [Польза]
2. [Действие] - [Польза]

[или] **Нет рекомендаций**
```

### 6. Спроси подтверждение
Используй `AskUserQuestion` для одобрения каждой рекомендации.

### 7. Обнови документацию
Для одобренных рекомендаций обнови файлы через Edit tool.

---

## Правила

### ✅ DO:
- Конкретика: файл + секция + действие
- Не более 3-4 рекомендаций
- Если проблем нет → "Нет рекомендаций"
- Минимум текста: 2-4 строки max (правило/пример/команда проверки)

### ❌ DON'T:
- Не обновляй без подтверждения
- Не дублируй между документами
- Не используй для тривиальных задач (<2 мин)
