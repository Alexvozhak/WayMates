## WayMates: План чистки и оптимизации проекта (MVP)

Дата: 2025‑09‑24

### 1) Текущее состояние (что уже есть)
- **Init Cypher**: констрейнты/индексы созданы (включая справочники).
- **Persist (JSON → Neo4j)**: `src/persist.ts` — AJV strict‑валидация, нормализация, upsert узлов и связей (Role/Grade/Industry/WorkDomain/Skill/SkillCategory).
- **Поиск когорты**: `src/search_cohort.ts` — матч по связям (IN_ROLE/IN_WORK_DOMAIN/USES_SKILL), coverage/expDelta, авто‑ослабление порогов.
- **Схемы**: строгая JSON‑схема в двух местах — `src/persist.ts` и `scripts/validate.ts` (дублирование).
- **Демо‑данные**: `data/contexts/*.json` + `query-context.json`.

### 2) Проблемы и дубли
- **Дубли схемы**: строгая JSON‑схема Story/Context описана в двух файлах (persist/validate).
- **Дубли подключения Neo4j**: создание драйвера и env в разных местах (persist/search).
- **Разночтение модели**: массивы в `Context` сохраняются и одновременно создаются связи; поиск уже на связях, но массивы остаются как «тень» и могут рассинхрониться.
- **tsconfig лишнее**: включён `jsx` и ряд опций, не используемых здесь.
- **package.json**: есть `ts-node` при использовании `tsx`; скрипты можно упростить, добавить `format/lint` позже.
- **Нехватка DX**: нет `.env.example`, README для быстрого старта, нет единых CLI‑флагов у скриптов.
- **Поиск: несовпадение с доком**: нет опции `currentOnly`; адаптация порогов частично расходится с документом по ladder.
- **Нет тестов**: базовые e2e на persist и cohort отсутствуют.

### 3) Цели чистки (критерии готовности)
- Одна общая схема без дублирования, импортируемая в `persist.ts` и `scripts/validate.ts`.
- Единый helper для Neo4j‑драйвера и окружения.
- Ясная позиция по массивам в `Context`: ВЫБРАНО — чистый граф. Не сохраняем массивы в `Context`, работаем только через связи.
- Упрощённые конфиги (`tsconfig`, `package.json`), добавлены `.env.example` и README.
- Поиск приведён к спецификации: ищем по ВСЕМ контекстам (без `currentOnly`), ladder с шагом 0.8 → 0.6 → 0.4 → 0.0.
- Минимальные тесты e2e на persist и cohort.

### 4) План корректировок (по шагам)
1. Схема данных
   - Вынести строгую JSON‑схему в `src/schema/story.strict.ts` (экспортировать объект и типы TS).
   - Подключить её в `persist.ts` и `scripts/validate.ts` via import.
2. Neo4j утилиты
   - Создать `src/neo4j.ts` с `createDriver()` и чтением `NEO4J_URI/USER/PASSWORD`.
   - Использовать в `persist.ts` и `search_cohort.ts`.
3. Контракты и модель
   - Поиск без `currentOnly`: по умолчанию ищем по всем контекстам пользователя.
   - Ladder: coverage 0.8→0.6→0.4→0.0; опыт ±1→±2→∞; домены on→off — строго в таком порядке.
   - Чистый граф (принято): убрать запись массивов из `UPSERT_CYPHER` в `persist.ts` (строки `c.languages = ...`, `c.frameworks = ...`, и т.д.). Сохраняем только связи: `IN_ROLE`, `HAS_GRADE`, `IN_INDUSTRY`, `IN_WORK_DOMAIN`, `USES_SKILL`.
4. Конфиги и скрипты
   - `tsconfig.json`: удалить `jsx`, привести `moduleResolution` к `bundler` или `node16` (на выбор), оставить минимальный набор.
   - `package.json`: убрать `ts-node`, добавить `format`/`lint` (плейсхолдер), упростить `start/dev`.
   - Добавить `.env.example` (NEO4J_URI, NEO4J_USER, NEO4J_PASSWORD).
   - Добавить `README.md` с шагами: запуск Neo4j, `npm run reseed`, поиск.
5. CLI (просто и понятно)
   - `persist.ts <path-to-json>` — позиционный аргумент.
   - `search_cohort.ts [path-to-params.json]` — опциональный позиционный (дефолт: `query-context.json`).
   - Вывод JSON с `request_id`, `ok`, `error?` без доп. флагов.
6. Нормализация (перенос в AI)
   - Удалить `normalizeContext` и вспомогательные функции (lowercasing/канонизация доменов) из `persist.ts`.
   - Считать входной JSON уже нормализованным AI; `persist` выполняет только валидацию схемы и запись узлов/связей без преобразований.
6. Тесты (минимум)
   - Отложено до отдельного согласования плана тестов (e2e/юнит/фикстуры).
7. Документация
   - Обновить `memory-bank/mvp_minimal_plan.md` (акцент на связях в поиске).
   - Короткая памятка про «ослабление порогов» в `memory-bank/cohort_search.md` — синхронизировать с кодом.

### 8) Калибровка coverage‑ladder (A/B‑тесты на одной выборке)
- Варианты стратегий (пример):
  - A: coverage 0.8→0.6→0.4→0.0; опыт ±1→±2→∞; домены on→off
  - B/C: перестановки порядка ослаблений (домены раньше/позже, опыт раньше/позже)
- Инструментирование:
  - Отдельные npm‑скрипты `exp:ladder:a|b|c`, без доп. флагов.
  - Логи — в stdout (JSON), редирект в файл (`> logs/a.json`).
- Датасет:
  - Фиксированный набор входов (несколько `query-context.*.json`) и фиксированный набор контекстов в БД
- Метрики:
  - total, средний `matchedSkills`, средний `coverage`, средний `expDelta`, доля результатов на каждой ступени
- Сценарии запуска:
  - `npm run exp:ladder:a > logs/a.json`
  - `npm run exp:ladder:b > logs/b.json`
- Аналитика:
  - Скрипт сравнения логов (простая агрегация) и выбор дефолтной стратегии на MVP
