## 1) TL;DR — что меняется

- **Фокус на контексте и навыках**, а не на жёстких маршрутах: пользователь собирает персональный план из проверенных путей авторов.  
- **Дистанция** = diff(текущий контекст → целевой контекст аватара/популяции).  
- **Скорость** = активный контекст (часы/нед + опциональные бусты деньгами), влияет на сроки, **не меняет сам diff**.  
- **Деньги** делятся на: **базовые расходы** (обязательные) и **ускорители (бусты)** — только бусты сокращают время.  
- **Dual‑diff планирование**: учитываем и ближайшего **аватара**, и **популяцию**; веса регулируем.  
- **Mid‑route attach**: подключаемся к маршруту аватара «с середины», если текущий контекст уже совпадает с промежуточным состоянием.  
- **Прозрачность**: возможность сравнить маршруты по оценкам, колву подтверждений, колву отзывов, времени, бусту тех, кто прошел маршрут   
- **Вторичка (агрегаты/эмпирика)**: считаем на лету + кэш, либо предвычисляем в аналитическом хранилище; вопрос финального места хранения остаётся открытым на MVP.
- маршрут состоит из троп (процессов). Каждая тропа развивает свой навык. Если по аналогии с гитом, то маршрут это весь репо, а тропы - это ветки, каждая ветка дает свою фичу, развивает свой навык.
- тропа (процесс) - в составе маршрута, развивает навык, аналог гит ветки, самостоятельная последовательность шагов, прокачивающая конкретный компонент контекста (навык, язык, артефакт, роль).  
- общество - другие пользователи платформы, авторы троп, имеющие отличающийся контекст по сравнению с нашим пользователем, но имеющие ту же цель.
- аватар - подмножество общества, другой пользователь платформы, автор маршрута, имеющий тот же контекст и ту же цель по сравнению с нашим пользователем.
- целевой контекст - контекст, которым обладал пользователем, когда добивался цели.
- как происходит выбор маршрута: 
1) загружается текущий контекст пользователя
2) загружается цель пользователя
3) на основе общества формируется приблизительный целевой контекст пользователя
4) на основе аватаром формируется окончательный целевой контекст пользователя
5) на основе аватара определяется **только перечень** (!) необходимых троп (список навыков, которые нужно докачивать)
6) на основе общества определяются самые оптимальные тропы для пользователя
7) если автор тропы ведет историю как менялся его контекст по ходу полной истории, то мы можем предложить пользователю начать эту тропу не с начала, а с этого места сразу
8) контекст пользоваться должен версионироваться. То есть целевой контекст необязательно будет текущим контекстом автором истории, это может быть 10ая версия, когда последняя, текущая - 15ая. Бд должна выдать именно целевой контекст в результатах пользователя. Наш пользователь не должен получать текущие контексты в результатах. В тоже время наш будущий аватар может стать настоящим не сразу а тоже на каком то своем шагу по этому маршруту.
9) контест пользователя после достижения цели обязательно фиксируется.
10) мы однократно находим всех маршруты аватаров и общества, а далее переходим к другому этапу (другой модуль), аналитическому. Он на вход получает наш текущий контекст и нашу цель, получает целевой контекст аватаров и общества, получает список обязательных типов троп (по тропам аватара), получает список троп общества по каждому типу. Далее на этом этапе, в этом программном модуле (узле) инкапусулирована вся бизнес-логика по подбору по стройке маршрута, за скелет берем маршрут и тропы аватара, но берем не его тропы а самые лучшие из тех, что предлагает общество. Как только увидели маршрут аватара, сразу видим его активный контекст (сколько он потратил времени, буста, сколько вышли все итоговые обязательные платежи по маршруту (виза - обязательный платеж, частный репетитор - буст)), оцениваем наш контекст (пассивный и активный) с аватаровским. В процессе перехода на общественные тропы мы видим удовлетворяем ли мы пассивному контексту и выработали ли квоту активного контекста. Выбранная комбинация общественных троп если превышает: 
- пассивный контекст пользователя, то это по идее приводит к дополнительным общественным тропам, которых нет у аватара;
- активный контекст пользователя, то платформа информирует пользователя (не дает ему подтвердить маршрут), что либо соглашаемся изменить под этот маршрут активный контекст (тратить больше времени и бустить больше), либо же такая комбинация троп нам не подходит.
11) во время выбора общественных троп, мы можем фильтровать/сортировать:
 - по колву прошедших эту тропу пользователей;
 - по оценке прошедших эту тропу пользователей;
 - по времени (от и до);
 - по обязательному платежу (до)
 - по проведенному размеру буста (до)
 - по получаемым артифактам?
 - по актуальности?
12) пассивный контекст - навыки достижения пользователя
13) активный контекст - колво времени и денег (обязательные расходы + буст), которые готов потратить пользователь для достижения цели
14) Целевой контекст это не точная величина, у всех пользователей были разные целевые контексты, когда они достигали одной и той же цели. Мы берем среднее (+медиана) по больнице, т.е. эмпирически

## 2) Терминология и базовые принципы

### 2.1 Дистанция (Distance)
**Дистанция** — композитная мера различия между текущим контекстом пользователя `C_user` и целевым контекстом `C_target` (обычно — контекст **аватара**).  
На MVP считаем через **косинусное сходство** над нормализованным представлением контекстов:
```
Distance(C_user, C_target) = 1 - cos_sim(φ(C_user), φ(C_target))
```
где `φ` — преобразование/нормализация признаков (навыки 0..10, CEFR→0..10, опыт, артефакты, роль).

### 2.2 Время 
время, которое требуется на прохохождение этой дистации 
---

### 2.2 Скорость (Speed)
-**Скорость** - величина для нас абстрактная, не осязаемая, не сильно прогнозируемая, самая непонятная. По сути это кол-во буста, измеряемого в деньгах, которое влияет на качество проведенного времени

### 2.3 Деньги: базовые vs бусты
- **Базовые расходы** (экзамены, визы, аренда) — обязательны, относятся к пассивному контексту.  
- **Бусты** (курсы, репетиторы, сервисы) — опциональны, ускоряют прохождение, увеличивая итоговую стоимость.
