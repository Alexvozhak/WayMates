# 🎯 Промпт для миграции на Orchestrator Architecture

## 📋 Контекст задачи

**Что было:** Hardcoded Cypher запросы в `SearchQueries.CURRENT_TO_TARGET` - статичные, негибкие.

**Что стало:** Динамическая архитектура с `QueryOrchestrator` - гибкие запросы на основе JSON пресетов.

## 🏗️ Новая архитектура

### Основные компоненты в `src/orcestrator/`:

1. **`QueryOrchestrator`** - центральный координатор
   - Управляет всем процессом генерации запросов
   - Координирует работу других компонентов

2. **`PresetsManager`** - управление конфигурациями
   - Загружает JSON пресеты из `config/presets.json`
   - Определяет `strictPresets` (строгие фильтры) и `flexiblePresets` (весовые поля)

3. **`SelectivityProfiler`** - оптимизация порядка полей
   - Анализирует селективность полей через `EXPLAIN` запросы
   - Возвращает оптимальный порядок для фильтрации

4. **`FieldSnippetsExtractor`** - модульные Cypher фрагменты
   - Содержит `FIELD_SNIPPETS` для каждого поля
   - Генерирует `strict` и `flexible` условия

5. **`CypherQueryBuilder`** - сборка итогового запроса
   - Объединяет сниппеты в полный Cypher запрос
   - Применяет оптимизированный порядок полей
