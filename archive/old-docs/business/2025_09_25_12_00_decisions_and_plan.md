## Принятые утверждения
- Сначала пишем e2e-тесты на текущей выборке (3 контекста), потом увеличиваем до 100+ JSON для масштаба.
- Тесты на Vitest; тестплан в отдельном MD (memory-bank/test_plan.md).
- Алгоритм поиска отрабатываем на большой выборке; пресеты добавляем как гибрид (Вариант C) с минимальными правками (объект PRESETS, ~20 строк).
- Форма отчёта — JSON с метриками (thresholds_used, total, avg_coverage и т.д.); рассмотрим интеграцию с готовыми tools вроде analytics для дашбордов.
- Cypher-схема ок: индексы/уникальность/связи логичны, улучшения минимальны (добавить weights в score для пресетов).
- Пресеты зависят от грейда (junior/middle/senior); другие факторы (домены) — post-MVP.
- Генерация 100 контекстов — скрипт + AI, под 10 query с 10 идеальными матчами каждый (Вариант A).
- Композитный индекс ON (c.period_start, c.period_end) — пока не делаем (post-MVP).
- Proficiency на USES_SKILL — post-MVP, как сложная задача.
- Тесты: Добавить vitest-benchmark для perf (Вариант A); отдельные suites для perf — группы тестов describe('perf tests').
- Анализ результатов — Вариант A (интеграция /davidwells/analytics).
- Кейсы для query-context.json: 8–10 файлов в data/request/ (базовый Senior, Junior низкий exp, Senior высокий exp, без доменов, с локацией, пустые навыки, избыток, нет матчей, пресет-тест, комбинированный). Связь с 100 контекстами: генерировать под них с 10 идеальными + шумом (Вариант A).
- Улучшения матчинга: Добавить explicit score с weights в QUERY_COHORT_CYPHER (matchedSkills*0.4 + coverage*0.3 + etc.); локации в score (weight 0.1).
?- Пересмотр коэффициентов в explicit scoring: countryMatch * 0.15 + cityMatch * 0.05 для большего акцента на страну (город как бонус).
