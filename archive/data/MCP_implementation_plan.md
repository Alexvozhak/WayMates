# План внедрения и доводки WayMates MCP (упорядоченный)

Цель: стабильный, валидируемый по Zod набор MCP‑инструментов с предсказуемыми ошибками, идемпотентными upsert‑ами, прозрачными логами/метриками и готовыми контрактами для MCPO.

---

## Этап 0 — Подготовка (источник истины и окружение)

- Источник истины: Zod‑схемы (FastMCP).
- Синхронизация: устранить расхождения между `src/schemas.ts` и `src/schemas-zod.ts` (оставить Zod, старые typebox — не использовать).
- Env (минимум): `MCP_PORT`, `MCP_TOKEN`, `NEO4J_URL`, `NEO4J_USER`, `NEO4J_PASSWORD`.

Критерий готовности: все входы/выходы tools описаны в Zod и импортируются из одного места.

---

## Этап 1 — Контракты инструментов (API MCP)

- Финализировать состав и сигнатуры:
  - `current_to_target`, `current_only`, `target_only`, `target_search` — вход/выход, ошибки.
  - `upsert_story_with_experience` — единая точка записи истории в Neo4j.
  - (Опционально) `generate_user_id` / `generate_context_id` / `generate_trail_id`.
- На границе каждого tool — валидация входов/выходов Zod, единый формат ошибок.

Критерий готовности: все tools зарегистрированы в `src/mcp-server.ts`, принимают/возвращают данные согласно Zod‑схемам.

---

## Этап 2 — Neo4j и Cypher (идемпотентность и атомарность)

- Идемпотентность upsert‑ов: использовать `MERGE`/уникальные ключи.
- Проверить согласованность параметров во всех `src/cypher/blocks/*.cypher`.
- Транзакции драйвера для сложных операций (атомарность).
- Индексация/уникальность:
  - Индексы: `userId`, `contextId`, `trailId`, `Skill.name`, `SkillCategory.name`.
  - Уникальные констрейнты на ID‑поля.

Критерий готовности: повторный вызов `upsert_story_with_experience` не создаёт дубликатов; профилирование Cypher без N+1.

---

## Этап 3 — Транспорт и безопасность MCP

- HTTP‑транспорт: включить/проверить `streamable_http` сервер.
- Health‑пинг: простой endpoint/метод для проверки живости и коннекта к Neo4j.
- Аутентификация: токен для server‑to‑server (MCPO→MCP) через `MCP_TOKEN`.
- Таймауты/лимиты: на уровне HTTP и Neo4j (конфиг драйвера).

Критерий готовности: smoke‑тест напрямую к MCP (без MCPO) проходит; 401/403 для неверной авторизации.

---

## Этап 4 — Ошибки, логирование, метрики

- Единый формат ошибок: `{ code, message, details? }` (валидация/бизнес/система).
- Map исключений Neo4j в понятные ошибки MCP.
- Структурные логи: вход/выход (без PII), время выполнения, размеры.
- Метрики (минимум): счётчик вызовов по tool, среднее/макс время, частота ошибок.

Критерий готовности: лог/метрики доступны и помогают отследить регресс/проблемы.

---

## Этап 5 — Совместимость с MCPO

- Имена и параметры tools задокументированы (для OpenAPI генерации MCPO).
- Ответы строго JSON‑совместимы (без несерилизуемых сущностей/дат без ISO‑строк).
- Размер/таймаут ответа: разумные лимиты и пагинация где нужно.

Критерий готовности: MCPO корректно генерирует OpenAPI; ручной вызов через MCPO `/tools` успешен.

---

## Этап 6 — Тестирование (пирамидой)

- Unit‑тесты: валидация входов (Zod), формат ошибок, простые кейсы.
- Интеграция: мок драйвера Neo4j или тестовый Neo4j; сценарии `upsert`/поиска.
- Контракты MCPO: фикстуры запрос/ответ под каждый tool.

Критерий готовности: unit+integration зелёные, контракты стабильно проходят.

---

## Этап 7 — Надёжность и производительность

- Идемпотентность повторных вызовов (особенно `upsert`).
- Ретраи с backoff на сетевые/временные ошибки.
- Избегать N+1 (агрегации/предзагрузки в Cypher).

Критерий готовности: повторяемые вызовы не ломают данные; латентность в заданных пределах.

---

## Этап 8 — DX и документация

- Env: описать `MCP_PORT`, `MCP_TOKEN`, `NEO4J_URL`, `NEO4J_USER`, `NEO4J_PASSWORD`.
- Документация: краткое описание каждого tool, примеры вход/выход, коды ошибок.
- Локальный запуск и smoke‑тесты: пошаговая инструкция.
- Версионирование: стратегия `toolName_v2` или поле `version` при несовместимых изменениях.

Критерий готовности: разработчик по README поднимает MCP и вызывает каждый tool за < 10 минут.

---

## Быстрые проверки по коду (final pass)

- `src/mcp-server.ts` — регистрация tools, Zod‑валидации, имена для MCPO.
- `src/persist.ts` — чистая библиотека без `main`; чёткое API для upsert.
- `src/neo4j.ts` — фабрика драйвера/сессий, таймауты/ретраи, единый импорт.

## Рекомендованный порядок выполнения (кратко)

1) Этап 0: Zod — источник истины, env.
2) Этап 1: контракты tools + Zod‑валидации на границе.

4) Этап 3: транспорт/безопасность MCP (HTTP, токен, health).
5) Этап 4: ошибки/логи/метрики.
6) Этап 5: совместимость с MCPO (OpenAPI).
7) Этап 6: тесты (unit→integration→контракты).
8) Этап 7: надёжность/производительность (ретраи, anti N+1).
9) Этап 8: DX/дока/версии.
10) Финальный pass по коду.
