# Goals Integration tests quality improvements (QA report)

**Component**: Integration tests

**Priority**: 🟡 P1

---

## User Story

Как разработчик, я хочу чтобы интеграционные тесты целей строго валидировали бизнес-логику, чтобы регрессии выявлялись рано, а падения тестов указывали на реальные баги, а не на проблемы качества тестов.

---

## AS IS

Тесты целей (TG1-TG7) имеют проблемы качества, выявленные QA-ревью: слабые утверждения (`.toBeGreaterThan(0)` вместо конкретных порогов), отсутствует валидация бизнес-логики (нет проверок разбивки скоров), потенциальные DRY нарушения.

---

## TO BE

Усиленные тесты целей: замена слабых утверждений на бизнес-правила пороги, добавление хелперов валидации структуры путей, валидация компонентов скора (логика сопоставления, качество пути), обеспечение падения тестов при регрессии бизнес-логики. Все 7 тестов валидируют реальные бизнес-требования, а не просто "возвращает что-то".
