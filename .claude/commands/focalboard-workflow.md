# Focalboard Task Management Workflow

## 🎯 Основной процесс: Подтверждение перед отправкой

**ВАЖНО**: Перед отправкой любой задачи в Focalboard, я **ВСЕГДА** должен:
1. Проанализировать контекст из кодовой базы
2. Подготовить полное описание задачи по шаблону
3. Показать тебе для проверки
4. Отправить только после твоего подтверждения

## 📋 Обязательный шаблон задачи

**ВАЖНО**: Focalboard **ПОДДЕРЖИВАЕТ** markdown форматирование! Используй полноценный markdown.

```markdown
## 🚀 [Краткое название - что делаем]

### 📝 Описание проблемы
- Что происходит сейчас (текущее состояние)
- Почему это нужно решить (проблема/возможность)
- Какой ожидаемый результат (целевое состояние)

### 🎯 Цель
Конкретная бизнес-ценность или техническое улучшение

### 📊 Контекст
- **Файл**: `путь/к/файлу.ts:строка`
- **Используется в**: название модуля
- **Зависит от**: другие модули/задачи
- **Алгоритм**: описание подхода

### ✅ Критерии приемки
- [ ] Критерий 1 (измеримый)
- [ ] Критерий 2 (проверяемый)
- [ ] Критерий 3 (конкретный)

### 🏷️ Метаданные
- **Метки**: backend, refactoring, bug-fix, feature, optimization, tests
- **Приоритет**: [Low/Medium/High/Urgent]
- **Оценка**: [часы/дни]
```

## Workflow в действии

### 1️⃣ Ты даешь задачу
```
User: "Нужно оптимизировать запрос поиска по навыкам"
```

### 2️⃣ Я анализирую и формулирую
```
Claude: Проанализировал код. Подготовил задачу для Focalboard:

[ПОЛНАЯ ФОРМУЛИРОВКА ПО ШАБЛОНУ С MARKDOWN]

**Отправить эту задачу в Focalboard? (да/нет/поправь)**
```

### 3️⃣ Ты проверяешь
```
User: "Да, отправляй" / "Поправь критерии приемки" / "Добавь в контекст X"
```

### 4️⃣ Я отправляю (или корректирую)
```
Claude: ✅ Карточка создана в Focalboard
📎 Прямая ссылка: http://localhost:8000/{board_id}/{view_id}/{card_id}
```

**Примечание**: Формат ссылки Focalboard:
- `{board_id}` - ID доски (из URL доски)
- `{view_id}` - ID представления (Board View) - получается из URL доски в браузере
- `{card_id}` - ID созданной карточки (возвращается API)

**ВАЖНО**: MCP API не возвращает `view_id`, его нужно взять из URL доски:
1. Открой доску в браузере: `http://localhost:8000`
2. URL будет: `http://localhost:8000/{board_id}/{view_id}`
3. Скопируй `view_id` из URL
4. Используй для формирования прямых ссылок на карточки

**Пример валидной ссылки**:
```
http://localhost:8000/bfir3cc9qsbbypr84gs9ozn9j1e/vz3zg5nsmtff8im6hupgxi8w9eh/cprn77zom7386teh396ue14q7ae
                     └──────── board_id ────────────┘ └──────── view_id ────────────┘ └──────── card_id ────────────┘
```

## Приоритеты задач

| Приоритет | Когда использовать |
|-----------|-------------------|
| Low | Техдолг, рефакторинг, nice-to-have |
| Medium | Новые фичи, улучшения UX |
| High | Баги, блокеры для других задач |
| Urgent | Критичные баги, production issues |

## Метки (Labels/Tags)

Стандартные метки для категоризации:

- **backend** - серверная логика, API
- **frontend** - UI/UX компоненты
- **database** - схема, миграции, оптимизация запросов
- **refactoring** - улучшение кода без изменения функциональности
- **bug-fix** - исправление ошибок
- **feature** - новая функциональность
- **optimization** - производительность, память
- **tests** - юнит/интеграционные тесты
- **documentation** - README, комментарии, диаграммы
- **infrastructure** - Docker, CI/CD, deployment

## Статусы задач

Типичные колонки в Focalboard:

- **Backlog** - Новая задача, ждет начала работы
- **To Do** - Готова к работе
- **In Progress** - В активной разработке
- **Review** - На код-ревью
- **Blocked** - Заблокирована внешними факторами
- **Done** - Выполнена и проверена

## Примеры хороших задач

### Пример 1: Оптимизация

```markdown
## 🚀 Оптимизация Cypher запроса для поиска по навыкам

### 📝 Описание проблемы
- Запрос в `buildSkillsMatchingQuery()` выполняется **2+ секунды** при 20+ навыках
- PROFILE показывает **15000+ db hits**, не используются индексы
- Блокирует UX при поиске кандидатов

### 🎯 Цель
Снизить время выполнения до **<200мс** для 95% запросов

### 📊 Контекст
- **Файл**: `src/core/search-query-builder.ts:245-312`
- **Метод**: `buildSkillsMatchingQuery()`
- **Используется в**: CurrentSearchService, TargetSearchService
- **Связан с**: snippets-extractor.ts (scoring logic)

### ✅ Критерии приемки
- [ ] PROFILE показывает использование индексов на `SkillCategory.name`
- [ ] DB hits < 1000 на типичном запросе (10-20 skills)
- [ ] Integration тесты проходят без изменений
- [ ] Добавлен performance benchmark тест

### 🏷️ Метаданные
- **Метки**: backend, optimization, database
- **Приоритет**: High (блокирует UX)
- **Оценка**: 4 часа
```

### Пример 2: Новая фича

```markdown
## 🚀 Добавить endpoint для bulk export результатов поиска

### 📝 Описание проблемы
- Пользователи хотят экспортировать найденных кандидатов в Excel
- Сейчас приходится копировать по одному
- Теряется структура данных при copy-paste

### 🎯 Цель
Возможность скачать результаты поиска в структурированном формате

### 📊 Контекст
- **Новый endpoint**: `POST /api/search/export`
- **Форматы**: CSV, XLSX, JSON
- **Использовать**: существующий SearchResult тип
- **Библиотека**: exceljs для генерации XLSX

### ✅ Критерии приемки
- [ ] Endpoint принимает `search_id` и `format`
- [ ] Поддержка 3 форматов (CSV, XLSX, JSON)
- [ ] Лимит 1000 записей за раз
- [ ] Unit тесты для каждого формата
- [ ] Документация в OpenAPI схеме

### 🏷️ Метаданные
- **Метки**: backend, feature
- **Приоритет**: Medium
- **Оценка**: 1 день
```

## Интеграция с кодом

При работе над задачей:

1. **Начало работы**: Переводим карточку в "In Progress"
2. **Коммиты**: Указываем номер задачи: `fix: optimize skill query #123`
3. **PR**: Ссылка на карточку в описании
4. **Завершение**: Переводим в "Done" + комментарий с результатами

## Важные соглашения

1. **Всегда спрашивай перед отправкой** - не создавай карточки автоматически
2. **ИСПОЛЬЗУЙ markdown** - Focalboard поддерживает полноценный markdown!
3. **Используй чекбоксы для критериев** - `- [ ]` в markdown
4. **Детальные критерии приемки** - чтобы было понятно, когда задача готова
5. **Указывай файлы и строки** - для быстрой навигации к коду
6. **Оценивай реалистично** - лучше переоценить, чем недооценить
7. **Используй метки** - для фильтрации и поиска
