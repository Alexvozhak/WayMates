# Plane Task Management Workflow

## 🎯 Основной процесс: Подтверждение перед отправкой

**ВАЖНО**: Перед отправкой любой задачи в Plane, я **ВСЕГДА** должен:
1. Проанализировать контекст из кодовой базы
2. Подготовить полное описание задачи по шаблону
3. Показать тебе для проверки
4. Отправить только после твоего подтверждения

## 📋 Обязательный шаблон задачи

**ВАЖНО**: Plane **ПОДДЕРЖИВАЕТ** полноценный markdown + rich text editor!

```markdown
# [Краткое название - что делаем]

## 📝 Описание проблемы

- **Текущее состояние**: Что происходит сейчас
- **Проблема**: Почему это нужно решить
- **Целевое состояние**: Какой ожидаемый результат

## 🎯 Цель

Конкретная бизнес-ценность или техническое улучшение

## 📊 Контекст

- **Файлы**: `путь/к/файлу.ts:строка-строка`
- **Модули**: Где используется
- **Зависимости**: От каких задач/компонентов зависит
- **Алгоритм/Паттерн**: Технический подход

## ✅ Критерии приемки (Definition of Done)

- [ ] Критерий 1 (измеримый и проверяемый)
- [ ] Критерий 2 (конкретный)
- [ ] Критерий 3 (с метрикой)

## 🧪 Тестирование

- [ ] Unit tests покрывают новый код
- [ ] Integration tests проходят
- [ ] ESLint: 0 errors
- [ ] TypeScript: компилируется без ошибок

## 📚 Дополнительно

- **Связанные задачи**: #123, #456
- **Референсы**: Ссылки на документацию, ADR, диаграммы
```

## Метки (Labels)

Стандартные метки для категоризации:

### По типу работы
- `feature` - Новая функциональность
- `bug` - Исправление ошибок
- `refactoring` - Улучшение кода без изменения функциональности
- `optimization` - Производительность, память
- `tech-debt` - Технический долг

### По слою архитектуры
- `backend` - Серверная логика, API
- `frontend` - UI/UX компоненты
- `database` - Схема, миграции, оптимизация запросов
- `infrastructure` - Docker, CI/CD, deployment

### По области
- `tests` - Юнит/интеграционные тесты
- `documentation` - README, комментарии, диаграммы
- `security` - Безопасность, уязвимости

## Статусы (States) в Plane

Типичный workflow для разработки:

```
Backlog → To Do → In Progress → In Review → Done
          ↓
        Blocked (временно)
```

- **Backlog** - Идеи, будущие задачи
- **To Do** - Готова к работе (приоритизирована)
- **In Progress** - Активная разработка
- **In Review** - На код-ревью
- **Blocked** - Заблокирована внешними факторами
- **Done** - Выполнена и проверена

```markdown
## 📝 Описание проблемы

- **Текущее состояние**: Запрос в `buildSkillsMatchingQuery()` выполняется **2+ секунды** при 20+ навыках
- **Проблема**: PROFILE показывает **15000+ db hits**, не используются индексы. Блокирует UX при поиске кандидатов
- **Целевое состояние**: Время выполнения **<200мс** для 95% запросов

## 🎯 Цель

Улучшить производительность поиска → быстрый отклик UI → лучший UX

## 📊 Контекст

- **Файлы**:
  - `src/core/search-query-builder.ts:245-312`
  - `src/orcestrator/snippets-extractor.ts:156-203`
- **Модули**: CurrentSearchService, TargetSearchService
- **Зависимости**: Neo4j GDS indices
- **Алгоритм**: Текущий - вложенные MATCH без индексов

## ✅ Критерии приемки

- [ ] PROFILE показывает использование индексов на `SkillCategory.name`
- [ ] DB hits < 1000 на типичном запросе (10-20 skills)
- [ ] P95 latency < 200ms (benchmark test)
- [ ] Integration тесты проходят без изменений

## 🧪 Тестирование

- [ ] Добавлен performance benchmark тест
- [ ] EXPLAIN/PROFILE output проверен через MCP neo4j-cypher
- [ ] Regression tests для edge cases (null, empty array)

## 📚 Дополнительно

- **Референс**: Neo4j Performance Best Practices
- **ADR**: Нет (тактическая оптимизация)
```

**Метаданные для Plane**:
- Проект: WayMates Core
- Метки: `backend`, `optimization`, `database`
- Приоритет: High 🟠
- Estimate: 4 SP

```markdown
# Добавить endpoint для bulk export результатов поиска
```

## Интеграция с кодом

При работе над задачей:

1. **Начало работы**: Переводим в "In Progress" → автоматически показывается в твоей очереди
2. **Коммиты**: Указываем номер задачи: `fix: optimize skill query PLN-42`
3. **PR**: Ссылка на задачу в описании → автоматический линк в Plane
4. **Завершение**: Переводим в "Done" + комментарий с результатами

## Важные соглашения

1. **Всегда спрашивай перед отправкой** - не создавай задачи автоматически
2. **ВСЕГДА выводи прямую ссылку** - формат: `http://localhost/{workspace_slug}/projects/{project_id}/issues/{issue_id}`
3. **ИСПОЛЬЗУЙ markdown** - Plane поддерживает полноценный rich text!
4. **Используй чекбоксы для критериев** - `- [ ]` в markdown
5. **Детальные критерии приемки** - чтобы было понятно, когда задача готова
6. **Указывай файлы и строки** - для быстрой навигации к коду (используй code blocks)
7. **Оценивай реалистично** - story points или часы/дни
8. **Метки обязательны** - минимум тип работы + слой архитектуры

## Story Points (оценка сложности)

| SP | Сложность | Время | Пример |
|----|-----------|-------|--------|
| 1 | Тривиальная | < 2 часа | Изменить текст, добавить константу |
| 2 | Простая | 2-4 часа | Простой CRUD endpoint, minor refactoring |
| 3 | Стандартная | 4-8 часов | Query builder функция, facade mapper |
| 5 | Сложная | 1-2 дня | Новый search mode, архитектурный рефакторинг |
| 8 | Очень сложная | 2-3 дня | Новый MCP server, интеграция с GDS |
| 13 | Эпик | 1 неделя | Новый core модуль, миграция архитектуры |

**Правило**: Если задача > 8 SP, разбивай на sub-issues!
