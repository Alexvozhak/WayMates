# Vikunja Task Management Workflow

## 🎯 Основной процесс: Подтверждение перед отправкой

**ВАЖНО**: Перед отправкой любой задачи в Vikunja, я **ВСЕГДА** должен:
1. Проанализировать контекст из кодовой базы
2. Подготовить полное описание задачи по шаблону
3. Показать тебе для проверки
4. Отправить только после твоего подтверждения

## 📋 Обязательный шаблон задачи

**ВАЖНО**: Vikunja НЕ поддерживает markdown форматирование! Используй простой текст с эмодзи.

```text
📋 Задача: [Краткое название - что делаем]

📝 Описание проблемы/сути:
• Что происходит сейчас (текущее состояние)
• Почему это нужно решить (проблема/возможность)
• Какой ожидаемый результат (целевое состояние)

🎯 Цель:
• Конкретная бизнес-ценность или техническое улучшение

📊 Контекст:
• Связанные файлы/модули (с путями)
• Зависимости от других задач/компонентов
• Технические детали (алгоритмы, паттерны, библиотеки)

✅ Критерии приемки (Definition of Done):
1. Критерий 1 (измеримый)
2. Критерий 2 (проверяемый)
3. Критерий 3 (конкретный)

🏷️ Метки: backend, refactoring, bug-fix, feature, optimization, tests
⚡ Приоритет: [1-5] (см. таблицу ниже)
📅 Оценка времени: [часы/дни]
```

## Workflow в действии

### 1️⃣ Ты даешь задачу
```
User: "Нужно оптимизировать запрос поиска по навыкам"
```

### 2️⃣ Я анализирую и формулирую
```
Claude: Проанализировал код. Подготовил задачу для Vikunja:

[ПОЛНАЯ ФОРМУЛИРОВКА ПО ШАБЛОНУ]

**Отправить эту задачу в Vikunja? (да/нет/поправь)**
```

### 3️⃣ Ты проверяешь
```
User: "Да, отправляй" / "Поправь критерии приемки" / "Добавь в контекст X"
```

### 4️⃣ Я отправляю (или корректирую)
```
Claude: ✅ Задача #123 создана в Vikunja
📎 Прямая ссылка: http://localhost:3456/tasks/{task_id}
```

## Приоритеты задач

| Приоритет | Название | Когда использовать |
|-----------|----------|-------------------|
| 1 | Unset | Не определен (по умолчанию) |
| 2 | Low | Техдолг, рефакторинг, nice-to-have |
| 3 | Medium | Новые фичи, улучшения UX |
| 4 | High | Баги, блокеры для других задач |
| 5 | Urgent | Критичные баги, production issues |

## Метки (Labels)

Стандартные метки для категоризации:

- **backend** - серверная логика, API
- **frontend** - UI/UX компоненты
- **database** - схема, миграции, оптимизация запросов
- **refactoring** - улучшение кода без изменения функциональности
- **bug-fix** - исправление ошибок
- **feature** - новая функциональность
- **optimization** - производительность, память
- **tests** - юнит/интеграционные тесты
- **documentation** - README, комментарии, диаграммы
- **infrastructure** - Docker, CI/CD, deployment

## Статусы задач

- **todo** - Новая задача, ждет начала работы
- **in-progress** - В активной разработке
- **review** - На код-ревью (можно добавить)
- **blocked** - Заблокирована внешними факторами
- **done** - Выполнена и проверена

## Примеры хороших задач

### Пример 1: Оптимизация
```markdown
📋 **Задача**: Оптимизация Cypher запроса для поиска по навыкам

📝 **Описание проблемы**:
- Запрос в buildSkillsMatchingQuery() выполняется 2+ секунды при 20+ навыках
- PROFILE показывает 15000+ db hits, не используются индексы
- Блокирует UX при поиске кандидатов

🎯 **Цель**:
- Снизить время выполнения до <200мс для 95% запросов

📊 **Контекст**:
- Файл: src/core/search-query-builder.ts:245-312
- Метод: buildSkillsMatchingQuery()
- Используется в: CurrentSearchService, TargetSearchService
- Связан с: snippets-extractor.ts (scoring logic)

✅ **Критерии приемки**:
1. [ ] PROFILE показывает использование индексов на SkillCategory.name
2. [ ] DB hits < 1000 на типичном запросе (10-20 skills)
3. [ ] Integration тесты проходят без изменений
4. [ ] Добавлен performance benchmark тест

🏷️ **Метки**: backend, optimization, database
⚡ **Приоритет**: 4 (High - блокирует UX)
📅 **Оценка**: 4 часа
```

### Пример 2: Новая фича
```markdown
📋 **Задача**: Добавить endpoint для bulk export результатов поиска

📝 **Описание проблемы**:
- Пользователи хотят экспортировать найденных кандидатов в Excel
- Сейчас приходится копировать по одному
- Теряется структура данных при copy-paste

🎯 **Цель**:
- Возможность скачать результаты поиска в структурированном формате

📊 **Контекст**:
- Новый endpoint: POST /api/search/export
- Форматы: CSV, XLSX, JSON
- Использовать существующий SearchResult тип
- Библиотека: exceljs для генерации XLSX

✅ **Критерии приемки**:
1. [ ] Endpoint принимает search_id и format
2. [ ] Поддержка 3 форматов (CSV, XLSX, JSON)
3. [ ] Лимит 1000 записей за раз
4. [ ] Unit тесты для каждого формата
5. [ ] Документация в OpenAPI схеме

🏷️ **Метки**: backend, feature
⚡ **Приоритет**: 3 (Medium)
📅 **Оценка**: 1 день
```

## Естественный язык для управления

После создания задачи можно управлять естественным языком:

```
✅ "Покажи все мои задачи"
✅ "Переведи задачу #123 в in-progress"
✅ "Добавь комментарий к #123: начал работу, нашел причину бага"
✅ "Отметь #123 как выполненную"
✅ "Создай подзадачу для #123: написать unit тесты"
```

## Интеграция с кодом

При работе над задачей:

1. **Начало работы**: Переводим в in-progress
2. **Коммиты**: Указываем номер задачи: `fix: optimize skill query #123`
3. **PR**: Ссылка на задачу в описании
4. **Завершение**: Отмечаем done + комментарий с результатами

Там можно:

## MCP Tools (под капотом)

Claude автоматически использует эти MCP tools:
- `mcp__vikunja__vikunja_tasks` - создание, обновление, список
- `mcp__vikunja__vikunja_projects` - управление проектами
- `mcp__vikunja__vikunja_labels` - работа с метками

## Важные соглашения

1. **Всегда спрашивай перед отправкой** - не создавай задачи автоматически
2. **ВСЕГДА выводи прямую ссылку на задачу** - формат: http://localhost:3456/tasks/{task_id}
3. **НЕ используй markdown в описании** - Vikunja не поддерживает, используй простой текст
4. **Детальные критерии приемки** - чтобы было понятно, когда задача готова
5. **Указывай файлы и строки** - для быстрой навигации к коду
6. **Оценивай реалистично** - лучше переоценить, чем недооценить
7. **Используй метки** - для фильтрации и поиска
