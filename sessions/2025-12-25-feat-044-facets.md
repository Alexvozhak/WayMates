## Рефлексия

### Как делать правильно

1. **Простые решения** — считать JSON size в KB вместо токенов (не нужен tiktoken)
2. **Конфиги в env.ts** — единый источник, можно тюнить без ребилда
3. **Pick/Extract из существующих типов** — не хардкодить дублирующие типы
4. **Explore agent для анализа архитектуры** — понимание на 90%+ перед кодом
5. **DRY в схемах** — базовая схема + extend для вариантов

### Как делать неправильно

1. **Optional поля в union** — лучше discriminatedUnion с явными вариантами
2. **Дефолты в разных местах** — types.ts + env.ts = путаница
3. **Хардкодить типы** — `type FacetField = "countryCode" | ...` вместо extract
4. **Давать пользователю менять лимиты** — это не UX выбор, а системные ограничения

### Инсайты

1. **Лимиты = не дефолты, а константы** — пользователь не должен их менять
2. **Progressive disclosure** — слишком много данных? покажи сводку + фильтры
3. **JSON size как proxy для токенов** — ~4 chars/token для ASCII, достаточно точно
4. **discriminatedUnion внутри discriminatedUnion** — можно, если разные дискриминаторы
5. **Core схемы не трогаем** — Facade адаптирует, не меняет контракты

### Наставления от пользователя

1. **"В env?"** — конфиги должны быть конфигурируемы
2. **"Union по needsFiltering"** — явный дискриминатор лучше optional полей
3. **"Есть же спец тип"** — переиспользовать существующие типы через extract
4. **"DEFAULT_LIMIT это не дефолт"** — это постоянное значение из config
5. **"Лимиты в разных местах"** — консолидировать в один источник
