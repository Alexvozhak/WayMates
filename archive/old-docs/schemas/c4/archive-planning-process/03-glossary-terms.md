# 📚 Глоссарий терминов WayMates

## 🔍 Поиск и сопоставление

### **Embedding (Эмбеддинг)**
**Что это**: Числовой вектор (список чисел), представляющий смысл текста  
**Пример**: "Python разработчик" → [0.123, -0.456, 0.789, ...]  
**Размерность**: 768 чисел для BGE-m3, 1536 для OpenAI  
**Зачем**: Компьютер может сравнивать смысл текстов через математику  

### **Cosine Similarity (Косинусное сходство)**  
**Что это**: Число от -1 до 1, показывающее насколько похожи два эмбеддинга  
**Пример**: 0.85 = очень похоже, 0.3 = слабо похоже  
**Формула**: `similarity = cos(angle_between_vectors)`  
**Зачем**: Находить семантически похожие истории  

### **Vector Index (Векторный индекс)**
**Что это**: Специальная структура данных для быстрого поиска по эмбеддингам  
**Тип в Neo4j**: HNSW (Hierarchical Navigable Small Worlds)  
**Аналогия**: Как индекс в книге, но для поиска по смыслу  
**Скорость**: Миллисекунды вместо секунд для поиска в миллионах записей

### **GraphRAG (Graph Retrieval Augmented Generation)**
**Что это**: Поиск информации через граф связей + векторный поиск  
**Этапы**: 1) Векторный поиск → 2) Расширение через граф → 3) Финальный результат  
**Преимущество**: Находит не только похожий текст, но и связанную информацию  
**Пример**: Ищем "Python" → находим Django, PostgreSQL, веб-разработку

### **Confidence Score (Уверенность)**  
**Что это**: Число от 0.0 до 1.0, показывающее надежность сопоставления  
**Компоненты**: Векторное сходство (40%) + График (30%) + Метаданные (20%) + Качество (10%)  
**Пороги**: >0.8 = автоодобрение, 0.6-0.8 = голосование, <0.6 = ручная проверка  
**Кто вычисляет**: AI система автоматически для каждого найденного совпадения

## 🗄️ База данных Neo4j

### **Node (Узел)**
**Что это**: Основная сущность в графе (человек, навык, страна)  
**Свойства**: Характеристики узла (имя, возраст, рейтинг)  
**Labels**: Типы узлов (:User, :Story, :Skill, :Location)  
**Пример**: `(u:User {name: "Иван", age: 25})`

### **Relationship (Связь)**  
**Что это**: Соединение между узлами с направлением  
**Типы**: :CONTAINS, :REQUIRES, :SIMILAR_TO, :FROM_LOCATION  
**Свойства**: Характеристики связи (вес, дата создания)  
**Пример**: `(story)-[:SIMILAR_TO {score: 0.85}]->(route)`

### **Cypher**
**Что это**: Язык запросов для Neo4j (как SQL для обычных БД)  
**Синтаксис**: MATCH (найти), CREATE (создать), WHERE (условие)  
**Пример**: `MATCH (u:User)-[:HAS_STORY]->(s:Story) RETURN s.title`  
**Особенность**: Визуально похож на рисование графа

### **HNSW Index**  
**Что это**: Hierarchical Navigable Small Worlds - алгоритм быстрого поиска векторов  
**Принцип**: Многоуровневый граф для эффективного приближенного поиска  
**Скорость**: O(log N) вместо O(N) для точного поиска  
**Trade-off**: Очень быстро, но результат приближенный (не 100% точный)

## 🛤️ Маршруты и истории

### **Story (История)**
**Что это**: Пользовательский рассказ о пройденном пути релокации  
**Структура**: Полный текст + метаданные + шаги + эмбеддинги  
**Статус**: draft → validation → approved → published  
**Использование**: Источник данных для создания и обновления маршрутов

### **Route (Маршрут)**  
**Что это**: Обобщенный путь достижения цели на основе множества историй  
**Компоненты**: Шаги + временные рамки + требования + статистика успеха  
**Отличие от Story**: Маршрут = паттерн, История = конкретный случай  
**Обновления**: Может дополняться новыми историями

### **StoryStep (Шаг истории)**
**Что это**: Одно действие или этап в истории пользователя  
**Типы**: skill_development, job_search, relocation, bureaucracy  
**Свойства**: описание + временные рамки + результат + эмбеддинг  
**Цель**: Детальное сопоставление с шагами маршрутов

### **RouteStep (Шаг маршрута)**
**Что это**: Обобщенное действие в маршруте на основе множества StoryStep  
**Данные**: Средние сроки + процент успеха + типичные препятствия  
**Источник**: Агрегация данных из связанных историй  
**Обновление**: Пересчитывается при добавлении новых историй

## 🤖 AI и обработка

### **NL2Cypher**  
**Что это**: Преобразование вопроса на естественном языке в Cypher запрос  
**Пример**: "Найди Python разработчиков в Германии" → `MATCH (u:User)-[:HAS_SKILL]->(:Skill {name: "Python"})-[:RELOCATE_TO]->(:Country {name: "Germany"})`  
**Технология**: LLM + примеры запросов + валидация  
**Безопасность**: Только READ-запросы, никаких DELETE/UPDATE

### **BGE-m3**
**Что это**: Multilingual многоцелевая модель эмбеддингов  
**Размерность**: 768 чисел на текст  
**Языки**: Поддерживает русский и английский  
**Преимущества**: Качественные эмбеддинги + быстрая работа + доступность

### **Semantic Decomposition (Семантическая декомпозиция)**
**Что это**: Разбиение истории на логические шаги с помощью AI  
**Алгоритм**: LLM анализирует текст → выделяет ключевые этапы → классифицирует типы  
**Результат**: Структурированные шаги вместо сплошного текста  
**Цель**: Точное сопоставление с существующими маршрутами

## 🎯 Валидация и модерация  

### **Auto-approval (Автоодобрение)**
**Когда**: Confidence score > 0.8  
**Действие**: Система автоматически принимает сопоставление  
**Контроль**: Логируется для последующего аудита  
**Риски**: Возможны ложные срабатывания, но редко

### **Community Review (Сообществное голосование)**  
**Когда**: Confidence score 0.6-0.8  
**Процесс**: Показываем случай опытным пользователям → голосование  
**Порог**: 70% за = одобрено, иначе отправляем на ручную проверку  
**Участники**: Пользователи с рейтингом 4+ звезды

### **Manual Review (Ручная проверка)**
**Когда**: Confidence score < 0.6 или спорные случаи  
**Кто**: Редакторы WayMates с экспертизой в релокации  
**Время**: До 24 часов на решение  
**Критерии**: Качество истории + релевантность + уникальность инсайтов

### **Validation Pipeline (Пайплайн валидации)**  
**Этапы**: AI анализ → Technical validation → Community/Manual review → Final approval  
**Цель**: Качество данных при максимальной автоматизации  
**Метрики**: % автоодобрений, время обработки, качество решений  
**Улучшение**: Обратная связь от пользователей для настройки порогов

## 📊 Метрики и аналитика

### **Similarity Score**  
**Что это**: Оценка похожести двух текстов/историй (0.0-1.0)  
**Источник**: Косинусное расстояние между эмбеддингами  
**Интерпретация**: 0.9+ = почти идентично, 0.7+ = очень похоже, 0.5+ = похоже  
**Использование**: Первичная фильтрация для дальнейшего анализа

### **Quality Score**
**Что это**: Оценка качества истории на основе множества факторов  
**Компоненты**: Полнота + структурированность + уникальность + рейтинг сообщества  
**Диапазон**: 1-5 звезд  
**Влияние**: Более качественные истории получают больший вес в confidence

### **Match Confidence**  
**Что это**: Итоговая уверенность в правильности сопоставления истории с маршрутом  
**Отличие от Similarity**: Учитывает больше факторов, не только текстовое сходство  
**Применение**: Основа для принятия решений о автоматизации  
**Обучение**: Система улучшается на основе обратной связи от пользователей

## ❓ Часто путаемые термины

### **Embedding vs Similarity Score**
- **Embedding**: Вектор чисел, представляющий смысл текста  
- **Similarity Score**: Число, результат сравнения двух эмбеддингов

### **Confidence vs Similarity**  
- **Similarity**: Только текстовое сходство (один фактор)
- **Confidence**: Комплексная оценка (много факторов)

### **Story vs Route**
- **Story**: Конкретная история одного человека  
- **Route**: Обобщенный паттерн на основе многих историй

### **Vector Search vs Graph Search**
- **Vector Search**: Поиск по смыслу текста (эмбеддинги)  
- **Graph Search**: Поиск по связям между сущностями
- **Hybrid**: Комбинация обоих подходов
