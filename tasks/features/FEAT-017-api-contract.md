# Core-Facade API Contract (DictionariesManager + FEAT-015,016)

**Component**: Core API, Facade MCP

**Priority**: 🔴 P0

---

## User Story

Как архитектор, я хочу четкий API контракт между Core и Facade, чтобы обе команды могли разрабатывать независимо без breaking changes и интеграция была гладкой.

---

## AS IS

Нет формального API контракта. Facade предполагает Core интерфейс на основе инспекции кода. Риск breaking changes когда Core эволюционирует. Нет версионирования, нет четких обязанностей (какой слой обрабатывает auth, нормализацию, валидацию).

---

## TO BE

Документированный API контракт: обязанности Core (канонические данные, бизнес-логика, persistence), обязанности Facade (NLP, auth, workflows, UI адаптация). TypeScript типы шарятся через пакет. DictionariesManager интерфейс определен (получение канонических имен, отправка на модерацию). tempId маппинг контракт (FEAT-015). CRUD операции контракт (FEAT-016). Стратегия версионирования для Core API. Обе команды могут эволюционировать безопасно.
