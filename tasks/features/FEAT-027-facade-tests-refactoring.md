# Facade Tests Refactoring

**Priority**: 🟡 P1
**ADR**: → ADR-022, ADR-026
**Status**: TODO

Реструктуризация тестов facade по техническим сущностям: `agents/`, `mcp-tools/`, `services/`.

---

## Правила работы

### ✅ Обязательно

| # | Правило | Детали |
|---|---------|--------|
| 1 | Обновлять FEAT-027 | После каждого этапа: ⬜ → ✅ в таблице |
| 2 | Тесты до показа | Запускать тесты перед показом результата на ревью |

### 🚫 Запрещено

| # | Правило | Причина |
|---|---------|---------|
| 1 | Пропускать этапы | Нельзя делать 2b пока 2a не завершён |
| 2 | Большие коммиты | Нельзя объединять несколько этапов в один коммит |
| 3 | Импровизация | Нельзя делать что-то не указанное в SESSION без согласования |
| 4 | Менять логику | Нельзя менять содержимое тестов, только перемещать файлы |
| 5 | Коммитить | Коммиты делает пользователь после ревью |

### 📋 Стиль работы

| Аспект | Правило |
|--------|---------|
| **Репортинг** | Детально: список что сделал, что переместил, вывод тестов |
| **При ошибках** | Фиксить импорты самостоятельно (не останавливаться) |
| **Комментарии** | Средне: что делаю и почему |
| **Инициатива** | Заметил странность/проблему → отметить, доложить в конце этапа |
| **Улучшения** | Спрашивать через AskUserQuestion, не делать самостоятельно |

### 🛠️ Codestyle

| Аспект | Правило |
|--------|---------|
| **Перемещение** | `git mv` (сохраняет историю файла) |
| **Именование** | Переименовать по шаблону (описательные имена) |
| **Imports** | Исправлять через `npx tsc --noEmit` (показывает сломанные) |
| **Проверки** | По модулям: `tsc → lint → tests модуля` |

### 🎯 Роль и миссия

**Роль**: Исполнитель + Помощник + Партнёр
- Идти строго по плану
- Предлагать улучшения
- Совместно принимать решения, обсуждать

**Миссия**: Порядок + Покрытие + Документация

**🚫 Антипаттерны**:
- Не принимать архитектурные решения самостоятельно
- Не спешить (качество важнее скорости)
- Не скрывать проблемы/странности
- Не усложнять
- Не додумывать бизнес-логику и архитектуру
- Не подгонять тесты под бизнес-код
- Не делать тесты фиктивными/театральными без бизнес-ценности
- Не оставлять тесты без бизнес-комментария (2-3 предложения перед тестом)

## Решения (→ FAQ Q71-Q80)

| Вопрос | Решение |
|--------|---------|
| Структура | `agents/`, `mcp-tools/`, `services/` |
| Внутри модуля | `unit/`, `integration/` |
| Naming | Описательные имена |
| Coverage | V8, только visibility |

## Целевая структура

```
tests/facade/
├── agents/
│   ├── cold-start/{unit,integration}/
│   ├── update-context/{unit,integration}/
│   └── upsert-context/{unit,integration}/
├── mcp-tools/integration/
├── services/integration/
└── helpers/
```
